# Upper-bounded requirements: install the closest versions available elsewhere.
#
# Same content as requirements.txt, with every exact pin turned into an upper
# bound. On a machine whose package index only offers older releases, pip then
# installs the newest version that is NOT newer than the one validated here.
#
#   Windows: .venv\Scripts\python.exe -m pip install -r requirements-compat.txt
#   Linux:   .venv/bin/python -m pip install -r requirements-compat.txt
#
# Then capture what was really installed and compare it with the reference:
#   python -m pip freeze > target-freeze.txt         # on the target machine
#   python tools/requirements_diff.py target-freeze.txt   # here, in the clone
#
# About the lower bounds kept below (GEMSEO 6, PySide6 6.6, Pydantic 2, NLopt
# 2.7, MCP 1.23, Claude Agent SDK 0.2): they are the ones the project states in
# pyproject.toml, so they are real requirements, not preferences.
#
# Red Hat Enterprise Linux 9 (glibc 2.34, x86_64), measured on PyPI 2026-09-28.
# The glibc floor of RHEL 9 is 2.34, so nothing has to be downgraded:
# - 92 entries are pure Python, 29 ship an accepted compiled wheel, 2 are
#   pure-Python sdists (MiniSom, xdsmjs), none is blocked.
# - the tightest wheels are the Qt ones: PySide6, shiboken6, PySide6_Essentials
#   and PySide6_Addons need glibc 2.34 exactly, which is what RHEL 9 provides;
#   numpy, scikit-learn, pillow and contourpy need 2.27.
#   The upper bounds above therefore stay useful: a later PySide6 needing glibc
#   2.35+ would not install on RHEL 9.
# - Python 3.12 comes from AppStream (python3.12, python3.12-pip): the system
#   python3.9 is below the requires-python of the project.
#
# Caveats:
# - The plugin gemseo_lso declares gemseo>=6.3,<7 and gemseo_claude_pilot
#   declares gemseo>=6,<7: on a machine whose GEMSEO is older than 6.3, install
#   the plugins with --no-deps, or relax their constraint in their own
#   pyproject.toml.
# - If pip reports a conflict, remove the bound of the package it names: this
#   file only exists to be adapted.
# - A range does not guarantee API compatibility. An older release may well
#   have a different API, which is exactly what the comparison must reveal.
