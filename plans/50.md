# 50 — Moved scripts find their data again

Status: Done
Depends on: 49
SPEC: § 4.2.3

## Goal

A script moved or renamed outside the application finds its runs and surrogates again in the user data directory, by a check of its fingerprint, then, when it was edited since, by a recursive comparison of its model (the user's request).

## Scope

In:
- the folder of a project found by the path its `project.json` records, never renamed;
- the fingerprint of the script and the tree of the model recorded at each save and opening;
- finding the folder of a moved script when it is opened, and telling the user.

Out:
- Asking the user to choose among several matching folders (plan 51).
- Removing the folders of scripts that were deleted.

## Steps

- [x] `project.json`: path, fingerprint, tree; folders found by their recorded path.
- [x] `find_moved`: moved folders only, fingerprint first, then tree; ambiguity reported.
- [x] Session records at save and opening; controller re-associates when a script is read.
- [x] MDAs named in generated scripts, so that the tree of a script read back is the tree saved.
- [x] Tests, SPEC, guide, changelog.

## Tests

- pytest:
  - a copied script does not take the folder of its original;
  - a moved script found by its fingerprint, then, edited, by its tree; a changed model not found;
  - two moved projects matching: none chosen, both reported;
  - end to end: saved, a run added, moved, opened again: the run found, the folder following the script.

## Acceptance criteria

- The tree recorded for every example equals the tree of its script read back.
- `python tools/check.py` passes.

## Implementation notes

- **Why the folder is never renamed**: the scripts of projects using surrogates refer to their models in it by an absolute path; renaming it would break them, and the script could then not be read to be recognized.
- **Only moved folders** are candidates: a folder whose file still exists belongs to it, so a copied script starts with no data.
- **Tree**: `[name, kind, children]` for each node, the kind being `assembly`, `driver:<kind>` or `component:<kind>`. It ignores ports and settings: an edited script whose nodes are the same is recognized.
- **MDAs** in generated scripts now get `name=` like chains: without it, a script read back named its MDA `MDAChain`, and its tree differed from the saved one. The golden scripts `sellar_mda` and `sellar_disciplinary_opt` changed accordingly.
- A folder holding nothing but its `project.json` is removed when the project is closed: a moved script without runs or surrogates has nothing to find.
