# 64 — Surrogates without pickles

Status: Done
Depends on: 63
SPEC: § 3 (script reader), § 4.2.3, § 7.4, § 15 (demos)

## Goal

Surrogates are no longer saved as pickles. Loading a pickle can run any code, so antivirus software (Microsoft Defender) quarantines the `.pkl` files the application writes, and users cannot tell a safe one from a malicious one. A surrogate is saved as its **training data**, an HDF5 file (`h5py`: a group `inputs` and a group `outputs`, one array per variable, in their order), next to its metadata (algorithm and settings); it is trained again when it is loaded, which takes a fraction of a second for the models the wizard offers. HDF5 is binary, fast (100,000 samples of 25 values: written in 0.01 s, read in 0.04 s) and exact; reading it runs no code. The generated script reads it with a short `read_training_data` function and builds the surrogate with `create_surrogate`: plain GEMSEO, no pickle.

## Scope

In:
- the wizard's training writes `<name>.h5` and trains the model on the data read back from it, so that the model measured is exactly the one a script rebuilds; the regression models whose training draws random numbers get a fixed seed (`random_state` is 0 by default in GEMSEO; `GradientBoostingRegressor` receives it through its `parameters`);
- the store saves and lists `<name>.h5` with `<name>.json`; the surrogate components record the algorithm and its settings;
- codegen: `create_surrogate("<algorithm>", read_training_data(<FILE>), disc_name=..., **settings)`, with the function `read_training_data` written once in the script;
- the script reader: a `SurrogateDiscipline` trained on data read from an HDF5 file is a surrogate component (with the metadata next to the file, as the wizard saved it; without, described by its algorithm);
- the demos (`examples/demoBiLevel`, `examples/wingBiLevel`) keep their training data in HDF5 instead of pickling their models;
- compatibility: surrogates and scripts of earlier versions (`.pkl`) still open and run as before; a pickle written by the user in a hand-written script is still read.

Out:
- converting existing `.pkl` surrogates automatically (training the surrogate again in the wizard replaces it by an HDF5 one).

## Implementation notes

- **HDF5 rather than CSV**, at the user's request: a first prototype wrote the samples as GEMSEO's CSV (`IODataset.from_csv`), which pandas reads back rounded in the last bit, and is slow on large samples. HDF5 is exact and fast; GEMSEO has no HDF5 reader for datasets, so the scripts hold a `read_training_data` function of seven lines (`h5py`, BSD, already installed with GEMSEO and listed in `THIRD_PARTY_NOTICES.md`). `pandas.to_hdf` is not used: it can pickle columns.
- **The model measured is the model rebuilt**: the worker writes the samples, reads them back with the same function and trains on them. All the regression models the wizard offers give the same predictions (to 1e-10) when `create_surrogate` trains them again from the file with the stored settings (a test for each). `random_state` is 0 by default in GEMSEO; `GradientBoostingRegressor`, which has no such setting, gets `parameters={"random_state": 0}` (`seeded_settings`), stored in the metadata and written in the script.
- **Training time** when a surrogate is used: 0.02 s for the RBF of the wing demo (200 samples), about 0.5 s for a Gaussian process on 60 samples. The script reader and the runs train the surrogates again each time.
- **The script reader** cannot see the call of a function written in the script: it records the HDF5 files opened for reading (by wrapping `h5py.File`) and takes the one whose samples equal the training data of the `SurrogateDiscipline`. The settings of the model are the arguments of `SurrogateDiscipline` that are not its own.
- **Ports without metadata**: samples written outside the application give the ports from the variables of the file, without training.
- **Compatibility**: a component whose `model_path` ends with `.pkl` still generates `SurrogateDiscipline(from_pickle(...))`; rediscovery and the description of a project's data count both `.h5` and `.pkl`. Old pickles are not converted: training the surrogate again replaces them.
- **Demos**: `demoBiLevel/maintenance.py` samples the fleet study once into `models/maintenance.h5`; its RBF now uses the default scaling of `create_surrogate` (min-max), like the application's surrogates, instead of none. `wingBiLevel/duo.py` keeps inputs and outputs in `models/<name>.h5` (the `.npy` of the inputs is gone) and enriches the file.
- `tools/smoke_installed.py` reports `FAIL demos` when it runs from a source checkout (the demos are shipped only in an installed package); unrelated to this plan.
