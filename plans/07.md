# 07 — Model tree and inspector

Status: Done
Depends on: 06
SPEC: § 8.3, § 8.7

## Goal

Add the Model tree (left panel) and the Inspector (right panel) with their base content, both synchronized with the canvas selection, and a reusable virtualized list component for large models.

## Scope

In:
- Virtualized list component (fixed row height) used by the tree and, later, by tables.
- Tree: Model › assemblies/drivers › components › ports; expand/collapse; selection sync with the canvas; inline rename; drag and drop to re-parent (`reparentNodes`); the context menu framework of plan 06.
- Inspector:
  - **Properties** section: name, description, type/kind (read-only), assembly mode (`auto | chain | parallel | mda`), `isolated`, `transparent` flags (stored now, used by later plans).
  - **Variables** section: virtualized table of ports (local name, direction, dtype, shape, unit, default, description), editable through `setPorts`; filter and sort.
  - Multi-selection: shows the common fields only.
- "Show in tree" / "Show in canvas" actions.

Out:
- Component-specific configuration editors (plan 10), global names and roles columns (plans 11, 15), driver editor (plan 15), link inspector (plan 12).

## Design

- Row height fixed (22 px) so virtualization stays a pure computation; overscan of 10 rows.
- The tree keeps its own expanded set (persisted in the project layout as `tree_expanded`) and auto-expands to reveal the selection.
- Editing a cell sends a command; the cell shows a transient error state if the command fails (message from the bridge error).
- Values are parsed in `table_model.js`: numbers, `[1, 2, 3]` arrays, shapes like `3` or `3x4` → `[3, 4]`.

## Implementation notes

- **Reusable components**: `components/virtual_list.js` (fixed 22 px rows, overscan 10, pure range logic in `lib/virtual_window.js`) and `components/editable_table.js` (sortable columns, filter box, cell editors `text` / `select` / `checkbox` / `button`, per-cell error state; header and body scroll horizontally together). Value parsing in `lib/table_model.js`: numbers, `[1, 2]` arrays, booleans, text; shapes `scalar`, `3`, `3x4`.
- **Tree** (`panels/tree.js`, rows from `lib/tree_flatten.js`): components are expandable to show their variables. Clicking a node shows its level on the canvas and selects it; double-click opens a container or fits the canvas on a component; the canvas context menu is reused; drag and drop onto a container sends `reparentNodes`. The expanded set is saved in `layout.tree_expanded` when the user toggles a branch (not when the selection reveals a node, so selecting does not modify the project).
- Renaming from the tree goes through the context menu (canvas in-place editor) or the inspector Name field, rather than an editor inside the tree row.
- **Inspector** (`panels/inspector.js`): shows the single selected node, or the current level when nothing is selected, or a count for multi-selections. Properties: name, type, description, assembly execution mode, "Flatten into the parent driver" (`transparent`), "Isolate variable names" (`isolated`). Variables (components): editable table (name, direction, type, shape, unit, default, description, remove) sending `setPorts` with the whole list, plus "Add variable". The table is updated in place after each patch. Drivers show a placeholder until plan 15.
- Checked in the real application: tree selection moves the canvas to the right level, expanding the optimizer shows its components, editing a unit and renaming from the inspector are applied and undoable, "Add variable" adds a port.
