# 28 — Executable wrapper runtime

Status: Not started
Depends on: 14
SPEC: § 7.5 (configuration), § 7.6 (descriptors), § 17 (risk 1)

## Goal

Provide a GEMSEO discipline that wraps an external executable through input file templates and output parsing rules (the Quick Wrap / File Wrapper equivalent), usable from generated scripts, with a reusable descriptor format.

## Scope

In:
- Study GEMSEO 6's executable-discipline base class (if any): decide whether `ExecutableDiscipline` subclasses it or is standalone; record the decision in the notes and SPEC § 17 risk 1.
- `runtime/executable.py`:
  - `ExecutableDiscipline(Discipline)` built from an `ExecutableSpec` (Pydantic);
  - command with tokens (`{input_file}`, `{output_file}`, `{workdir}`), environment variables, timeout;
  - working directory policy: one temporary folder per execution (unique, safe with `n_processes > 1`), retention `always | on_error | never`, files to copy in;
  - input templates with `{{variable}}` and `{{variable:format}}` markers, scalars and vectors (vector rendering configurable: separator, one per line);
  - output rules: `regex`, `marker` (line after a marker, column n), `key=value`, `table` (block → vector), `file` (path of a produced file);
  - error handling: expected return codes, error patterns in stdout/stderr, clear exception messages naming the rule that failed;
  - logging of the command, duration and working directory.
- Descriptor file `*.gpbwrap.json` = serialized `ExecutableSpec` + ports metadata (units, descriptions); load/save helpers.
- Catalog: descriptors found in plan 09 become droppable components of kind `executable`; introspection reads ports from the descriptor.
- Codegen: `ExecutableDiscipline.from_descriptor("path/to/wrapper.gpbwrap.json")` when the component comes from a descriptor; inline `ExecutableSpec(...)` otherwise (readable, one argument per line). Import from `gemseo_process_builder.runtime`.
- Example `examples/external_code/`: a tiny Python "solver" script with input/output files, its descriptor and a project using it.

Out:
- The graphical wrapper editor (plan 29).

## Design

- Template rendering and output parsing are pure functions with thorough unit tests; only one or two tests actually spawn the tiny solver (each must stay under one second: the solver must not import heavy libraries).
- Paths in descriptors are relative to the descriptor file.

- Parsing: each rule type, missing marker error, malformed number error.
