## Design

- Preferences file: `QStandardPaths.AppConfigLocation/preferences.json`, schema-versioned Pydantic model: `catalog_paths`, `python_interpreter`, `max_undo` (500), `layout` (panel sizes and collapsed states), `recent_projects`, `log_level`, `stop_timeout_s` (10), `allow_concurrent_runs` (false). Invalid file → backup and defaults, with a warning in the console.
- Actions have ids like `file.open`, `edit.undo`, `run.start`. Native menus are defined in Python from a static list that mirrors the JS registry (id, label, shortcut). Clicking a native menu item emits `action.invoke { id }`; JS runs the action. JS sends `actions.state { id: enabled }` updates to keep native menus in sync (`actions.setState` method).
- Shortcuts are handled in JS (the web view has focus), except when a text input is focused. Native menus show the shortcut text but do not register it, to avoid double triggering.
- Console: bounded buffer (10,000 lines), level filter, text search, copy, clear. Each line: time, level, source (`app`, `worker`, `run:<id>`), message.
- Visual: system UI font, 13 px base; neutral grays, one accent blue; component type colors defined as tokens for later plans.

## Implementation notes

- **Single source for actions**: the action list (id, menu, label, shortcuts) lives in `app/actions.py`. The page loads it with `actions.list`, attaches behaviors with `app.actions.handle(id, {run, enabled, checked})`, and pushes enabled/checked states back to the native menus with `actions.setState` (batched per microtask). Native menus only display the shortcut text; `file.quit` is the only native action.
- **Shared page services** are in `static/js/app.js` (`app.api`, `app.actions`, `app.statusBar`, `app.layout`, `app.tabs.{left,center,bottom}`, `app.console`), filled by `main.js`. Later panels import `app` from there (importing `main.js` would create cycles).
- `TabGroup.open({id, title, closable, onClose})` opens dynamic tabs (used later for results, N2, XDSM…); `setBadge(id, count)` shows counters (Problems).
- Panel sizes are stored in the preference `layout.panels` (`{left, right, bottom}: {size, collapsed}`); other keys of `layout` are kept for later plans.
- The Console renders at most the last 2,000 matching lines (the buffer keeps 10,000). It becomes virtualized once the virtual list of plan 07 exists — to be revisited in plan 32 if needed.
- `app.logs` returns the last 500 records so that lines logged before the page connected are not lost. Records from the bridge module itself are not forwarded (feedback loop).
- The "Keyboard shortcuts" and "About" dialogs are already implemented here (generic `components/modal.js`), earlier than plan 26 planned.
- `--preferences PATH` command-line option added (used by scripted runs to avoid touching the user's preferences).
- A scripted run of the app (outside the test suite) checked: panel collapse/expand from actions, layout persisted in the preferences file, shortcut dialog opened from the action and closed with Escape, Python logs shown in the Console.
