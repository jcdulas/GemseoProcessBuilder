# 45 — Examples of components

Status: Done
Depends on: 44
SPEC: § 7.0

## Goal

"When we create a Python function, an Analytic, a class, an executable wrapper or a surrogate, there should be a button creating an example component: it asks where to save the .py, and creates a working template."

## Scope

In:
- `app/api_component_examples.py`:
  - `componentExample.create`: a Python function, a Python class or an executable wrapper written where the user chooses;
  - `componentExample.samples`: the example run of a surrogate;
- `gemseo_process_builder/templates/`: the example function, and the external code;
- page:
  - `panels/component_examples.js`, the callouts in the inspectors of the components not set up yet;
  - the complete example of the Analytic formulas;
  - the example button next to New Python file….

Out:
- Examples of drivers (the examples of the repository show whole studies).

## Steps

- [x] Templates and service, with tests.
- [x] Surrogate example: samples in the service, training and saving in the page.
- [x] Inspector callouts and buttons.
- [x] SPEC, guide, changelog.

## Tests

- pytest:
  - a Python function example read by GEMSEO (ports and defaults), never replacing a file;
  - a Python class example that computes (area 20, aspect ratio 5);
  - an executable example whose descriptor loads, with its files next to it, never replacing a file;
  - the templates equal to `examples/external_code`;
  - the example samples read by the results and trained on (R² above 0.95 in cross-validation);
  - the Latin hypercube;
  - no example for other kinds.

## Acceptance criteria

- In the app:
  - the Analytic example gives the ports span, chord, area and aspect_ratio;
  - the surrogate example trains "Wing example" (R² 0.994 in cross-validation), shows its run in the Runs panel and gives the component its ports.
- `python tools/check.py` passes.

## Implementation notes

- **Surrogate**:
  - The service only writes the run. The page trains and saves with `surrogates.train` and `surrogates.save`, as the wizard does: the document changes stay in the Qt thread, and the training in the worker.
  - The samples are computed in the UI process with the standard library: formulas of the example, not user code.
- **Templates**: `gemseo_process_builder/templates/` holds files written for the user; ruff and mypy leave them out, like users' code.
- **Wrapper**: the descriptor takes the name the user chooses; `solver.py` and `input.tmpl` go next to it, as the descriptor refers to them.
- **Inspector**: it is rebuilt when the function, the descriptor or the surrogate of the component changes, so the callout gives way to the configuration.
