# 22 — Native GEMSEO post-processings

Status: Done
Depends on: 15, 19
SPEC: § 12.3, § 8.6

## Goal

Let users run GEMSEO's own post-processings on a finished run, configure them with generated forms, and browse the resulting images in a gallery.

## Scope

In:
- Worker methods:
  - `postproc.list(run)`: post-processings applicable to the run (optimization vs. DOE), from GEMSEO's post-processing factory, with their settings schemas (reuse `settings.schema` of plan 15);
  - `postproc.run(run, name, settings)`: loads `history.h5`, executes the post-processing with `save=True`, `show=False`, file format SVG (PNG fallback when the post-processing does not support SVG), writes into `postproc/<name>-<timestamp>/`, returns the file list; cancellable.
- "Post-processing" sub-tab in the Results tab: list of available post-processings with short descriptions, settings form (generated), Run button, gallery of produced images (thumbnails, click to open full size, zoom/pan), delete a result, open folder.
- Images served to the page through the `gpb://` scheme with a dedicated route for run files (`gpb://run/<run_id>/<path>`), restricted to the run folders of the open project.
- Remember the last settings per post-processing in the project.

Out:
- Including these images in the report (plan 31).

## Design

- matplotlib must use the `Agg` backend in the worker (set before importing pyplot).
- Long post-processings (SOM, QuadApprox) show a spinner and can be cancelled; their tests use tiny data so they stay under one second, or are covered only by the list/dispatch tests if even tiny data is too slow (record it).

## Implementation notes

- Worker (`workers/postproc_methods.py`):
  - `postproc.list` offers GEMSEO's post-processings (Animation and TopologyView are left out). A run whose algorithm is a DOE algorithm only gets BasicHistory, Correlations, ParallelCoordinates, ParetoFront, RadarChart, SOM and ScatterPlotMatrix.
  - Each post-processing comes with its description and the lenient JSON schema of its settings, without the output settings (`save`, `show`, `file_path`, `directory_path`, `file_name`, `file_extension`), which the application sets itself.
  - `postproc.run` validates the settings, forces the matplotlib `Agg` backend and reads `history.h5` with `OptimizationProblem.from_hdf`. It saves SVG files, falling back to PNG when SVG is refused, into `postproc/<name>-<YYYYmmdd-HHMMSS>/` with a `settings.json`, and returns the list of files. A failure removes the output folder.
  - `postproc.results` lists the earlier outputs, newest first.
- Cancelling: the worker serves one request at a time and GEMSEO cannot be interrupted, so `postproc.cancel` restarts the worker. The half-written folder has no `settings.json`, so it is not listed. The page reports a `cancelled` error (new `ErrorCode.CANCELLED`) without showing a dialog.
- App (`app/api_postproc.py`): `postproc.list/results/run/cancel/delete/reveal`, with one post-processing at a time. `delete` and `reveal` accept only a direct child of the run's `postproc/` folder.
- Scheme handler: the `gpb://run/<run_id>/<path>` route serves only files of the runs indexed by the open project, through `RunStore.folder_of`. It uses the same path checks as the static files, and runs of other projects, traversal attempts and folders are rejected.
- Page:
  - `views/results/postprocessing.js` adds the "Post-processing" sub-tab:
    - the post-processings listed with their descriptions (the list scrolls on its own);
    - the settings form (`settingsForm`, kind `postprocessing` in `essential_fields.js`);
    - Run, a spinner and Cancel while running;
    - a gallery of the outputs (settings used, thumbnails, Open folder, Delete).
  - `components/image_viewer.js` shows images full window: wheel zoom around the pointer, pan by dragging, double click to fit, arrow keys to move between images, Escape to close.
  - The last settings of each post-processing are kept in the project layout (`extra.postproc_settings`) after a successful run.
  - `askConfirmation` moved to `components/modal.js`, and `openModal` gained `onClose` (Escape now answers "no").
- Tests:
  - `tests/python/results/fixtures/sellar_run/history.h5` holds a 67 KB Sellar MDF history of 3 iterations.
  - OptHistoryView takes about 0.5 s once pyplot and the post-processing factory are imported in conftest.
- Smoke-tested on a Sellar MDF run:
  - OptHistoryView (4 SVG files) and ConstraintsHistory appear in the gallery and open in the viewer.
  - The ObjConstrHist settings are remembered.
  - A cancelled Correlations run reports `cancelled`, the worker restarts, and the next post-processing works.
