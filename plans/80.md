# 80 — The 3D view of `nastran_view` opened from a run

Status: Done
Depends on: 21, 79; `nastran_view`
SPEC: § 3.4, 12.2, 14.4, 17 (open point 14); [SIZING_LOOP_EVOLUTIONS.md](../docs/SIZING_LOOP_EVOLUTIONS.md) § 5 (GPB-E4)

## Goal

In an architecture study, a row of the results is a whole structure. From a row or a point of the Results, the user opens its model, layout and reserve factors in `nastran_view`, and compares two architectures, without any WebGL or canvas view in the page of the application: `nastran_view` is another application, in its own window and process. Milestone M4 of the sizing loop (ECOSYSTEM-EVOLUTIONS.md § 6).

## Scope

In:
- prerequisites (SPEC § 17, open point 14): the command line of `nastran_view` (one folder, `--compare`, `--title`), and, from `gemseo_nastran`, the evaluation folders, their manifest `evaluation.json` and the name of the input giving their root folder;
- worker: `nastran_view` found in the Python of the runs (`importlib.util.find_spec`); the manifests indexed under the root of a run (the value of the root input in the snapshot of the run), matched to the rows by the values of the design variables or by the hash of the architecture parameters; a malformed manifest reported and skipped;
- bridge methods `view3d.available(runId)` and `view3d.open(runId, rows)`; `nastran_view` started with the interpreter of the runs, by an argument list (`subprocess.Popen(command, close_fds=True)`, no shell), as the code editor is;
- UI: **Open in the 3D view** in the context menus of the Data table, the XY plot and the scatter matrix, and on the best evaluation of the Summary; **Compare in the 3D view** with two rows selected; disabled with the reason in the tooltip when `nastran_view` is missing or the row has no folder; the menu state in a pure `lib/view3d.js`.

Out:
- any WebGL or canvas view in the page (the rule of CLAUDE.md stands);
- copies of the evaluation folders in the run folder (they belong to `gemseo_nastran`, SPEC § 12.1);
- viewers of other packages.

## Implementation notes

- Contracts: `nastran_view` 7c38c9e takes a sizing folder of `gemseo_nastran` (`python -m nastran_view <folder> [--compare <folder>] [--title <text>]`); `gemseo_nastran` 7672a4e names the root `store_path` and writes `evaluation.json` schema 1. SPEC § 17 open point 14 closed.
- One worker method, `view3d.state` (`workers/view3d_methods.py`), instead of two: whether `nastran_view` is located in the Python of the runs (without importing it), the store of the run (the input `store_path` of the `gemseo_nastran` components in the snapshot, typed or default; empty: `gemseo_nastran_store` in the temporary folder, `gemseo_nastran`'s default), the manifests of kind `sizing`, schema 1, status `done` (others skipped, malformed ones and other schemas reported), and the folder of each evaluation. An evaluation matches a sizing when its design variables equal, to 1e-9, the requested values of one of the plan's requests, the values at the keys of the request in `inputs` (the obtained ones), or plain numbers of `inputs` (a sizing without a planner); the last manifest written wins. Bridge: `view3d.state(run_id)` and `view3d.open(run_id, evaluations)` (`app/api_view3d.py`), the command started with the interpreter of the runs, `close_fds`, no shell, its title the run and the evaluations.
- UI: the context menu of a row of the Data table and of a point of the XY plot (Open; Compare with the one other evaluation brushed), a button on the best point of the Summary; disabled with the reason as a tooltip (`MenuItem.title`, new). The state of each run is asked once and forgotten when the runs change (`views/results/view3d.js`); the logic is in `lib/view3d.js`. Not done: the scatter matrix (its points have no context menu yet).
- Checked by hand: on the store of the standalone run of the architecture study (plan 79), the four evaluations matched their sizing folders, and `nastran_view` (its own environment) loaded one folder as a scene and two as a comparison (4 s; its window not opened). Not done: the whole path from the window of the application, which needs `gemseo_nastran` and `nastran_view` in one Python of the runs.
