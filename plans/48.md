# 48 — The script alone is the project

Status: Done
Depends on: 47
SPEC: § 4.2, § 4.2.1, § 4.2.2, § 15.3

## Goal

A project is its GEMSEO script, and nothing else: no hidden side file. Opening a script always reads it and lays the diagram out; the runs and surrogates are found again next to it. Projects of older versions (`.gpb.json`) still open and are saved as scripts; the examples become scripts (the user's choices: keep nothing beside the script, remove the project format from saving).

## Scope

In:
- the script reader: renamed variables, isolated instances and their links, surrogates, fast mode and processes, stable ids, name and description from the docstring;
- saving a script only, an incomplete project kept in its autosave;
- opening a script by reading it, the runs and surrogates found again (`results/rediscovery.py`);
- the save dialog (scripts only), older projects saved as scripts;
- the examples written as scripts from their projects, moved to the test fixtures.

Out:
- Keeping positions, units or descriptions typed on variables (the user chose to keep nothing beside the script).

## Tests

- pytest:
  - isolated instances read with their links; name and description from the docstring;
  - a script without scenario gives the model itself;

  - runs and surrogates found again, a run mapped to its driver by its path of names;

## Acceptance criteria

- Every golden script and example read back gives the same results when generated again and run (external code and surrogate with their files).
- The example scripts run on their own.
- `python tools/check.py` passes.

## Implementation notes

- **Ids**: `n-<names from the root>` (`n-Optimizer.Sellar1`), stable when a script is read again.
- **Runs** refer to their driver by id; a run found again is mapped through its `driver_path` to the id of the node read. `settings.runs_dir` is not kept: runs are in `<project name>.runs/`.
- **Project name**: the first line of the docstring of a script the application wrote (it has a `Generated by GEMSEO Process Builder` paragraph); the paragraphs between them are the description. The docstring of the project script no longer says `from <file>`.
- **Incomplete projects**: `save` returns with the project still modified and writes the autosave at once, so that it is newer than the script and offered for recovery; opening a script with a newer autosave recovers it without reading the script. If recovery is refused, the script is read.
- **Opening a script** leaves the project unmodified (it used to be marked modified when read).
- **Older projects** keep their `.gpb.json` path, so that their runs and surrogates resolve; *Save* goes to *Save as…* when the file is not a script. The suggested file name is the project name as an identifier (`sellar_mdf.py`).
- **Examples**: `beam_chain`, `optimization_sequence` and `wing_sizing` only existed as project files, so the project files are the reference (`tests/python/fixtures/examples/`), loaded with `examples/` as base folder so that their relative paths still lead to the files of the examples. The surrogate example has no script (its surrogate is built in the application); `tools/smoke_installed.py` still runs it, and takes no argument anymore.
- The `project.gpb.json` snapshot in each run folder stays: it records the project as it was run.
- **Nested studies**: a discipline executed while scenarios exist used to run (initial values computed before the study); when it holds a scenario adapter, it is now the process of the script, so that a chain with an optimization as one of its steps is not read as that optimization alone.
- **Long strings** in generated scripts (analytic formulas) are written in parentheses, cut into implicitly concatenated pieces when too long, as `ruff format` keeps them. The examples are checked like the golden scripts (ruff with its default settings, mypy apart since module names repeat).
- `*.py.lock` is ignored by git.
