## Goal

Every component and container has a **Cache** setting in the inspector — last execution (default), none, all executions in memory, all executions in an HDF5 file — written in the script as one `set_cache` call and read back from it. An expensive evaluation kept in a file is not computed again by a later run with the same inputs. Milestone M4 of the sizing loop (ECOSYSTEM-EVOLUTIONS.md § 6).

## Scope

In:
- the owner's decision on where the file caches live (SPEC § 17, open point 11), before any code;
- model: `cache {type, tolerance, file, node}` in the `config` of components and containers, absent for the default;
- inspector: the Cache field, the tolerance under Advanced, the file (default `caches/<project name>.h5` in the data of the project) and the node (default: the path of names, `Study/Sizing`);
- worker methods `cache.inspect` (the entries of a node, counted with `h5py`) and `cache.clear` (removes the node);
- the fingerprint of the component of each node, recorded beside the file (`<file>.gpb.json`) when a run starts; the inspector warns when it differs and offers Clear or Keep;
- codegen: `set_cache` on the object the process uses, after the typed values and before the remapping, with a comment; the `CACHE_FOLDER` path constant;
- script reader: `set_cache` calls recorded and turned back into the setting;
- rules (§ 9.1): a file cache with `n_processes > 1` on Windows (Error, quick fixes: one process, in memory); a fingerprint that differs (Warning);
- data of the project: the `caches/` folder; *Save as…* moves the default caches.

Out:
- **Resume** and the history saved after each evaluation (plan 78);
- caches shared between projects.
