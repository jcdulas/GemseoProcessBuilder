# 18 — Live run monitoring

Status: Done
Depends on: 17
SPEC: § 11.5, § 8.1 (status bar)

## Goal

Show what a run is doing while it runs: logs in a run-specific console tab, execution states on the canvas, progress and stop controls, and a live convergence chart.

## Scope

In:
- Console: one tab per active run (`run:<id>`), auto-scroll with "pause on scroll up", level filter; closing the tab does not stop the run.
- Canvas and tree: node status dots and header tint (`pending | running | done | failed`), a subtle pulse for `running`, reset when a new run starts; aggregated state for containers (running if any child runs, failed if any failed).
- Progress: status bar progress bar (current/total, unit), elapsed time, Stop button; the same in the toolbar area.
- Live chart panel in a new center tab "Run: <id>" (the Results tab of plan 20 will take over this tab):
  - optimization: objective history and max constraint violation vs. iteration;
  - DOE / parametric: sample count and a simple scatter of the first two design variables vs. the first response.
- JS run state store: accumulates `run.event` messages per run with bounded memory (keeps every iteration up to 100,000 points, then decimates the display).

Out:
- Full results views, persistence and reopening (plans 19–21).

## Design

- Charts follow the dataviz guidance available to the implementing agent (load the `dataviz` skill before writing chart code): neutral palette from the CSS tokens, readable axes, no chart junk.
- Updates are batched with `requestAnimationFrame`; at most one redraw per frame.

## Implementation notes

- Pure libraries:
  - `lib/run_accumulator.js` reduces runner events to series. Iterations keep the first objective, the largest violation (max(g, 0), |h|) and feasibility; samples keep the first two inputs and the first response. `batch` events are unpacked.
  - `decimate()` keeps the first, last, lowest and highest point of each bucket. Stored series are halved beyond 100,000 points.
  - `lib/status_aggregation.js`: a container is failed if any child failed, running if any runs (or if some are done while others wait), done when all are done, pending when all wait.
  - Tests are in `tests/js/run_accumulator.test.js` (one file for both libraries).
- `services/run_state.js` (`RunStates`):
  - It keeps one accumulator per run from `run.started`, `run.updated`, `run.event`, `run.log` and `run.finished`.
  - Listeners are notified at most once per frame (`requestAnimationFrame`).
  - Node states come from the last run, aggregated for containers, and are reset when a new run starts.
- Canvas (`views/canvas/status.js`) marks each drawn node with a `run-<state>` class and a dot in the corner of its header: gray pending, blue pulsing running, green done, red failed. Running and failed nodes get a colored border. States update without redrawing the nodes, and the pulse is off with `prefers-reduced-motion`. The tree shows the same dot before the node name.
- Console: each run opens a bottom tab "Run <driver>" (a `ConsolePanel` fed by `run.log`, with level filter, search and auto-scroll paused when scrolled up). Closing it does not stop the run.
- Status bar: driver and status, a progress bar with count and unit (full once completed, since an optimization often converges early), elapsed time updated every second, and a Stop button.
- Live chart (`views/run_live/live_chart.js`): a center tab "Run: <driver>".
  - Summary: status, progress and the best feasible objective.
  - Optimization: the objective curve, plus the largest constraint violation curve when there are constraints.
  - DOE and parametric studies: a scatter of the first two inputs colored by the first response, with the range in the title. Up to 5,000 points are drawn, taken at regular intervals; min/max decimation suits curves, not clouds.
  - Colors come from the CSS tokens (accent, warning); axes have 5–6 ticks and titles name the variables. Redraws follow the run notifications and a `ResizeObserver`.
  - No `dataviz` skill is available in this environment; the charts follow its principles (neutral palette, readable axes, no decoration).
- Smoke-tested:
  - Sellar MDF: 8 iterations, best feasible `obj = 3.18339`, the three disciplines end in `run-done`, the run tab shows the logs, and the status bar reads "8/100 iterations 0:03".
  - A 3,000-sample LHS draws its cloud live.
