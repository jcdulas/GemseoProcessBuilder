# 43 — Python classes written from the inspector

Status: Done
Depends on: 42
SPEC: § 7.3

## Goal

The user wants to create the Python file of a discipline from the inspector: the file, the class, its variables. Their choices:
- the code of the computation is written in their own editor;
- a table of the inspector generates the declaration of the variables in the class, without touching `_run`.

## Scope

In:
- `core/discipline_file.py`: the source of a new module, and the variables of a class read and rewritten between markers (pure, `ast` only);
- `app/api_python_files.py`:
  - `pythonFile.create`, `pythonFile.variables`, `pythonFile.setVariables`, `pythonFile.open`;
  - the watching of the files of the Python components;
- the `code_editor` preference;
- page:
  - `lib/discipline_variables.js`;
  - `panels/discipline_file.js` (the creation dialog, the table, *Open in editor*);
  - the inspector rebuilt when the file or class of a component changes.

Out:
- The same for Python function components (their variables are the arguments and returned names of the function).
- An editor of code inside the application (the user chose their own editor).

## Acceptance criteria

- A Python class component: *New Python file…* writes `wing.py`; the component shows the ports `span`, `chord` and `area`. Adding an output in the table adds its port; the code of `_run` is unchanged.
- `python tools/check.py` passes.

## Implementation notes

- **Generated class**:
  - GEMSEO 6.3 API: `self.io.input_grammar.update_from_names(self.INPUTS)` and `self.io.input_grammar.defaults = {…}` in `__init__`, and `_run(self, input_data) -> dict`.
  - The attributes `INPUTS` and `OUTPUTS` are plain literals, read back with `ast.literal_eval`.
- **Units**: not in the table; they are given per port in the Variables section, as for the other components. Writing them in the class would need an attribute read by the application only.
- **Editor**:
  - Visual Studio Code is `code` or `vscode` on the path depending on the machine (and `code-insiders`); on Windows, its install folders are also looked at;
  - never the program associated with `.py` files: on Windows it can be Python itself, which would run the file;
  - on Windows, the quotes of a configured command are removed (`shlex` in non-POSIX mode keeps them).
- **Watching**: `QFileSystemWatcher` on the files of the Python components, added again after each change (some editors replace the file). Changes are grouped for 300 ms; the worker imports the file under a name made of its modification time, so it reads the new version.
- **Inspector**: it is rebuilt when the file or the class of the shown component changes; otherwise it keeps its fields, and their focus.
