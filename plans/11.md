Status: Not started

## Goal

Implement, in pure Python with no GEMSEO dependency, the rules that turn the project into resolved variables: global names, implicit and explicit couplings per scope, namespaces, container ports, aggregated links and feedback loops. Everything later (canvas links, validation, codegen, N2) reads the resolver output.

## Scope

In:
- Scope definition: the root model and each driver open a scope; assemblies do not (their children belong to the enclosing scope), except isolated ones which add a namespace prefix.
- Global names: default = local name; explicit link sets the target's global name; manual override; namespace prefix `<node name>:` for isolated nodes (nested isolation concatenates prefixes).
- Couplings per scope: producer of each global name, consumers, implicit vs explicit, duplicate producers (reported as issues).
- Derived container ports (§ 5.4) and aggregated links between containers seen from a level.
- Dependency graph between the direct children of each container; strongly connected components; feedback edges for display (edges going "backwards" with respect to the displayed order, per SCC).
- Incremental use: a `Resolution` object computed per scope and cached by document revision; recomputed only for scopes touched by the last changes.
- Bridge method `resolve.couplings(scope)` and a `resolution.updated` event.

Out:
- Canvas rendering of couplings (plan 12), validation messages (plan 13), units (plan 27), drivers' exposed ports (plan 23; keep a hook for it).

## Design

- `ResolvedPort`: node id, local name, global name, direction, source of the global name (`default | link | override | namespace`).
- `Coupling`: global name, producer (node, port) or `None` (free input of the scope), consumers, kind per consumer (`implicit | explicit`).
- `ScopeResolution`: couplings, free inputs, outputs, issues (`duplicate_producer`, `multiple_explicit_links`, `link_to_missing_port`, `loop_in_chain`, `dependency_in_parallel`), and per-container `DerivedPorts` and `AggregatedLink`s.
- Links always reference (node id, local port name); global names never appear in the stored links, so renames stay safe.
- Performance: resolving the 2,000-component synthetic model (plan 32 generator; build a smaller one here) must take well under one second.

## Tests

- Sellar: implicit couplings `y_1`, `y_2`, loop between Sellar1 and Sellar2, free inputs `x_local`, `x_shared`.
- Explicit link between different names changes the consumer's global name; deleting the link restores it.
- Duplicate producers, two explicit links to one input, link to a missing port.
- Isolated assembly: two instances of the same component do not conflict; explicit link crosses the isolation.
- Derived ports of nested assemblies; aggregated link counts.
- Feedback edges on a 3-node loop in displayed order.
- Performance guard: a 300-component generated model resolves in < 200 ms.
