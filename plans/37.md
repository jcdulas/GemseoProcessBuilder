# 37 — Start and end of a workflow

Status: Done
Depends on: 36
SPEC: § 8.2

## Goal

A start circle and an end circle on the canvas, holding the inputs and the outputs of the workflow. Choices made with the user:

- the end holds the final results (the outputs no node uses) and the outputs the user chooses;
- the start shows the inputs and lets the user type their values in one place;
- every level has its start and end.

## Scope

In:
- `core/workflow_io.py`: the inputs and outputs of a level;
- `exposed_outputs` on containers;
- `workflow.io` and `workflow.setInput`;
- the circles in the scene, their links, their placement around the nodes or above and under a chain;
- the inspector of the start (values) and of the end (results);
- dragging a node onto the end to show its outputs.

Out:
- The values of the results after a run (the Results tab shows them).

## Implementation notes

- **Inputs** (`workflow_io`):
  - walk the components of the level, through drivers and groups, each with the variables its drivers set (design space and parameter levels);
  - an input is a global name used by a component, computed by no component of the level, and set by none of its drivers.
  - Its value is the one of its first port (`default`, `default_text`, unit).
- **Outputs**:
  - `final` when no component of the level uses the variable;
  - a variable used only by a driver (an objective, a constraint) is final: it is a result of the workflow.
  - `exposed_outputs` (new field of containers, a cosmetic property: it changes neither the resolution nor the validation) adds other outputs; `others` lists the rest.
- **Limit**: the same global name used in two driver scopes is one input; typing its value sets both.
- **`workflow.setInput`**: `SetPorts` on every component using the input, in one `execute_many` ("Set <name>").
- **Scene** (`lib/scene.js`, `terminalScene`):
  - pseudo-items `start:<level>` and `end:<level>` (`terminal`), placed on the left and right of the nodes, or above the first and under the last node of a chain;
  - `io` links: plain curves (routing around nodes made loops), one per linked node, with the count of variables. They are not drawn above `MAX_TERMINAL_LINKS` linked nodes.
  - The circles are excluded from rectangle selection, node drag, auto-layout and context menus. Their positions are not stored.
- **Page**:
  - `canvas.io` is refreshed with the couplings and after every document change (the chosen outputs are cosmetic, so no `resolution.updated` follows them);
  - a click on a circle or an `io` link shows `terminalSection` in the inspector (through `linkFocus`, with `refresh()` when the variables change);
  - dragging a node onto the end offers its outputs not yet shown, or those of the components inside a dragged container.
