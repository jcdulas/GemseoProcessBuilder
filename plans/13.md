# 13 — Static validation and Problems panel

Status: Done
Depends on: 12
SPEC: § 9.1, § 8.8 (Problems), § 8.2 (validation state on nodes)

## Goal

Run the static validation rules continuously, list the results in the Problems panel with click-to-locate and quick fixes, and show the validation state on nodes and in the tree.

## Scope

In:
- Rule framework: each rule is a small function `(project, resolution) → list[Issue]`, registered with an id, a default level and a description.
- Rules available at this stage (from SPEC § 9.1):
  - duplicate producers for a global name in a scope;
  - more than one explicit link to an input;
  - dtype or shape mismatch on a coupling;
  - loop in a `chain` assembly, dependency in a `parallel` assembly;
  - component whose introspection failed, or with missing linked ports;
  - free input without a default value (warning);
  - unused output (info, can be disabled in preferences).
- Continuous validation debounced by 300 ms after each patch, on the touched scopes only; `validation.updated` event.
- Problems panel: sortable list (level, message, location path), filter by level, count badge on the tab, click → navigate the canvas to the node's level and select it.
- Quick fixes: "Switch to MDA" (assembly mode), "Isolate namespace", "Remove extra link", "Re-introspect". Each quick fix is a command, hence undoable.
- Node badges (red/orange border + tooltip listing issues) and tree icons.
- Menu action `Model › Validate` (F7) forcing a full validation.

Out:
- Driver-related rules (plan 15), unit and variable-type rules (plan 27), dry run (plan 16). The framework must make adding them a matter of registering a function.

## Design

- `Issue`: `code`, `level` (`error | warning | info`), `message` (English, user-oriented, no jargon in simple mode), `node_id`, optional `port`, optional `link_id`, `quick_fixes` (ids).
- Issues are stable across revisions (same `code` + location → same key) so the panel does not flicker.
- Validation runs in the UI process (pure Python, fast); the performance guard is < 1 s on the large synthetic model (plan 32 checks it).

## Implementation notes

- **Framework** (`core/validation.py`): rules are functions `(ValidationContext) -> list[Problem]` registered with `@rule(name)`; the context holds the project, its resolution, the introspection errors and user options. `Problem(code, level, message, node, port, link, quick_fixes)` with a stable `key` (`code:node:port:link`); problems are sorted errors first. Rule modules live in `core/rules/` and are imported by `validate()`; later plans add modules (drivers in plan 15, units and types in plan 27).
- **Rules** (`core/rules/structure.py`): resolver issues (`duplicate_producer`, `multiple_explicit_links`, `link_to_missing_port`, `loop_in_chain`, `dependency_in_parallel`), `incompatible_coupling` (type and size, `core/compat.py` mirrors `lib/link_compat.js`), `introspection_failed`, `missing_port`, `free_input_without_default` (warning), `unused_output` (info, controlled by the `show_unused_outputs` preference).
- **Quick fixes** (`core/quick_fixes.py`): `isolate_namespace`, `remove_link`, `switch_to_mda`, `switch_to_auto` (undoable commands) and `reintrospect` (asks the worker again).
- **Service** (`app/validation_service.py`): validates 300 ms after document changes, project changes, introspection status changes and preference changes; `validation.updated {problems, fix_labels}`; methods `validation.run`, `validation.state`, `validation.quickFix {key, fix}`. Validation runs in the UI process (pure Python).
- **Page**: Problems panel with per-level filters, count badge on the tab (errors + warnings), click to show the node on the canvas, quick-fix buttons; red/orange border and tooltip on canvas nodes; colored names in the tree; Model › Validate (F7) runs the validation and shows the panel. The dry run is added in plan 16.
- Checked in the real application: two components producing `y` → one error with the fix "Isolate the variable names of this node", B outlined in red, the fix removes the error.
