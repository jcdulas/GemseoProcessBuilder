## Goal

The pilot talks to Claude for real: through the user's own Claude Code (the default, with their subscription) or with an API key. A budget per run bounds the calls and the tokens. Tests never reach the network.

## Scope

In, in `plugins/gemseo_claude_pilot/`:
- `backends/claude_code.py`: `ClaudeCodeBackend`, on `claude-agent-sdk`: the pilot's tools served by an in-process MCP server, every built-in tool of Claude Code off, no user or project settings loaded, `ANTHROPIC_API_KEY` blanked for the Claude Code process so that the subscription login is used; errors mapped to the backend errors; a check of the login with `claude auth status`;
- `backends/api.py`: `ApiKeyBackend`, on `anthropic`: Messages API with tools, the system prompt and tools cached, the assistant turns sent back as received, typed errors mapped, timeout and retries;
- `auth.py`: the API key, from `ANTHROPIC_API_KEY` then the OS keyring; writing and deleting it in the keyring (for the preferences of plan 61);
- `backends/__init__.py`: `create_backend(name)`, the name from `GEMSEO_CLAUDE_PILOT_BACKEND` by default (`claude_code`, `api_key` or `off`);
- `exchange.py`: the handling of tool calls separated from the loop, so that a backend that runs its own loop (Claude Code) and one that returns one turn at a time (API, fake) share it;
- `budget.py`: the budget of a run (calls, tokens, estimated cost with an API key) and `pricing.py`;
- `pilot.py`: the backend by default, its check before the run, the budget.

In, in the repository: the dependencies and their licenses (`THIRD_PARTY_NOTICES.md`), the spec.

Out:
- The preferences, the Copilot tab and panel (plan 61). The runner (plan 60).

## Implementation notes

- **Dependencies**: `claude-agent-sdk` 0.2.160, `anthropic` 1.8, `keyring` 25.7, all MIT; the SDK's wheel does not bundle the Claude Code CLI (open point 4 settled). `mcp` 2 needs Pydantic 2.12 while GEMSEO 6.3 caps it at 2.11.9: the plugin requires `mcp>=1.23,<2` (1.30 works). `tools/third_party_notices.py` lists the plugin's dependencies in a section of their own (32 more, all permissive).
- **Two shapes of backend**: `Backend.send` returns one turn (API key, fake); `LoopingBackend.converse` runs the loop itself (Claude Code) and calls back for each tool call. The answers are shared: `exchange.ToolCalls` handles the read tools, the decision and its one correction, whoever runs the loop. A turn sent back to the API is the content received (`Message.raw`), thinking blocks included.
- **Claude Code**, from the SDK's source: `tools=[]` passes `--tools ""` (no built-in tool); `setting_sources=[]` loads no settings; `permission_mode="dontAsk"` refuses any tool not pre-approved; the options' `env` is added to the inherited one, so `ANTHROPIC_API_KEY=""` is what blanks a key of the environment; a string prompt works with in-process MCP servers (the SDK always streams). The working folder is an empty folder of the temporary directory. `claude auth status` gives the login as JSON; only the login state and the subscription are kept (not the email).
- **Errors**: Claude Code reports `authentication_failed`, `billing_error` (a refused login), `rate_limit` (the plan's limits) on its assistant messages; a missing CLI or package is a `BackendUnavailableError`, which turns the pilot off at once like a refused login.
- **Budget**: 30 calls and 1,000,000 tokens by default; the cost is estimated with a key only (`pricing.py`, per model), 0 with a subscription. When spent, recorded once as a `status` `budget`, and no more call is made.
- **The `off` backend name**: `GEMSEO_CLAUDE_PILOT_BACKEND=off` runs scenarios as is. The plugin tests set it, so that no test can reach Claude.
- **Smoke test**, Claude Code with a Max subscription, on Sellar (budget of 3 calls): 42 s, a start review, an event call (SLSQP at the bounds, judged normal: the Sellar optimum is there), and at the end a stop decision (converged to 3.18339 in 8 of 40 evaluations, `c_1` active); 12,400 input and 2,800 output tokens, 32,000 read from the cache. The API key backend was not run for real: no key on this machine.
- **Tests and time**: importing `anthropic` and `mcp` takes several seconds, and the Windows keyring about two seconds the first time; the plugin tests import them at collection time. During this plan, the machine ran at 94-100 % CPU (other programs): the full check failed four times on timing-sensitive tests of the application (three times `test_run_manager.py::test_stop`, whose fake runner must answer within 0.3 s, once another), while a direct run of the whole suite passed (762 passed, 1 skipped), and so did the last full check.
