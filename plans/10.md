# 10 — Components and introspection

Status: Done
Depends on: 09
SPEC: § 7.1, § 7.2, § 7.3, § 4.1 (ports)

## Goal

Give the Analytic, Python function and Python class components their configuration editors and compute their ports through worker introspection, so that dropped components show real inputs and outputs.

## Scope

In:
- Worker method `component.introspect(config)` for the three kinds:
  - **analytic**: parse expressions with sympy, check syntax, inputs = free symbols, outputs = left-hand sides;
  - **python_function**: import the function, read ports as `AutoPyDiscipline` does (signature for inputs and defaults, return statement names for outputs);
  - **python_class**: import the class, build it with `init_args`, read input and output grammars (names, types, shapes when known, default values).
- Worker method `component.init_signature(ref)`: the `__init__` parameters (name, annotation as a simple type, default) to build the `init_args` form.
- Port merge rules when re-introspecting: keep user-edited metadata (unit, description, overridden global name) for ports that still exist; mark removed ports that are still linked as "missing" (a validation error in plan 13).
- Inspector configuration editors:
  - analytic: expressions editor (one line per output `y = …`), live syntax check (debounced 400 ms);
  - python function / class: reference picker (catalog entry or free `module:attribute`), `init_args` form, "Re-introspect" button.
- Introspection runs automatically after a drop and after a configuration change; the node shows a spinner, then its ports or an error badge.
- Command `setComponentConfig` (undoable; introspection results applied through `setPorts` in the same transaction when they arrive).

Out:
- Executable wrapper and surrogate kinds (plans 28, 30); unit checks (plan 27); simple `init_args` forms are enough here — the JSON Schema form generator comes in plan 15 and replaces them.

## Design

- dtype mapping from grammars: numpy float arrays → `float`, int → `int`, complex → `complex`, `str` → `str`, anything else → `object`. Shape is `[n]` when a default value or the grammar gives it, otherwise `[]` with `shape_known = false`.
- Introspection results are cached in memory by (config hash, source mtime) in the worker.
- Introspection requests are queued and deduplicated per node (only the latest config matters).

## Implementation notes

- **Ports come from GEMSEO itself** (`workers/component_methods.py`, worker methods `component.introspect {kind, config}` and `component.init_signature {config}`): the worker builds `AnalyticDiscipline(expressions)`, `AutoPyDiscipline(function)` or `Class(**init_args)` and reads `discipline.io.input_grammar` / `output_grammar` (names and `defaults`). dtype and shape come from the default values (numpy arrays); outputs without defaults get `shape_known = false` (analytic outputs are `[1]`). Units given by the `component` decorator are applied. Modules are referenced by file (`module_path`) or installed module (`module`).
- `sympy` added as a dependency (BSD license): GEMSEO's `AnalyticDiscipline` needs it. Variables named like sympy's special symbols (`S`, `N`, `E`, `I`, `O`, `Q`) are refused with a clear message instead of sympy's cryptic error. Note: with GEMSEO, an analytic output used in another formula is also an input of the discipline (expressions are evaluated independently).
- **Service** (`app/component_service.py`): detects added components and configuration changes from the document patches (fingerprint of kind + config), debounces 400 ms, asks the worker, merges the result (`core/ports.py`: user units, descriptions, global names and typed defaults are kept; vanished ports still used by links stay, marked `missing`) and applies it with `document.execute(SetPorts, undoable=False, content=True)` — new `content` flag of `Document.execute`. Ports therefore always follow the configuration, including after undo. Opening a project does not re-introspect components that already have ports.
- Status per component (`component.status` event: running / done / error): "…" or "⚠" (with the error as tooltip) in the node header, and the message in the inspector.
- **Inspector configuration editors** (`panels/inspector_component.js`): analytic expressions as `output = formula` lines (parsed in `lib/expressions.js`, committed 600 ms after typing); function and class: module file with a native Browse dialog (new bridge methods `dialog.openFile` / `dialog.openFolder`), function or class name; class constructor arguments form built from `component.initSignature` (a simple form; the JSON Schema forms come in plan 15). A "Re-read variables" button forces an introspection. For introspected kinds, the Variables table only allows editing unit, default and description.
- The analytic and AutoPy GEMSEO modules (and sympy) are imported at test collection in `conftest.py` to keep each test under one second.
- pytest keeps only the temporary folders of failed tests (`tmp_path_retention_policy = "failed"`, count 1): deleting many old temporary folders during the first `tmp_path` setup took several seconds on Windows.
