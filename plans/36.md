# 36 — Execution arrows and chains built with arrows

Status: Done
Depends on: 35
SPEC: § 6.1, § 8.2

## Goal

Show the order in which assemblies run their content, and build chains by drawing arrows. The user asked whether blocks could be chained with arrows, run in parallel or as "if" blocks. They chose the execution arrows and building chains with arrows for now; "if" blocks (not native in GEMSEO) are left out.

## Scope

In:
- the rank of each node of a chain, and the mode of an assembly in its header;
- execution arrows between the nodes of a chain, at the level shown or in an assembly expanded in place;
- the fork and the join of a parallel block expanded in place;
- dragging the execution handle of a node onto another node of the same chain to make it run right after;
- a validation error when a node of a chain runs before the results it uses, with the "run automatically" fix.

Out:
- "If" blocks (conditional branches). GEMSEO has no conditional discipline: they would need generated Python code, and they break gradients.

## Implementation notes

- **Order check**: `Resolver.check_chain_order` runs after the loop check of a chain. A node ranked before one of its producers is reported once per chain (`chain_order`, error), naming the pairs (`Stress before Loads`). Its quick fix is `switch_to_auto`: a fix command gets the problem only, not the resolution, so it cannot compute an order.
- **Scene** (`lib/scene.js`):
  - `SceneItem.order` is the rank of a node in a chain (from 1).
  - `executionLinks` adds links of kind `execution`, with a filled `mark` (arrowhead, fork or join dot) and the `container`:
    - between consecutive nodes of the chain shown (the level itself, or an expanded assembly);
    - from a fork under the header of an expanded parallel assembly to each branch, and from each branch to a join at its bottom.
  - `executionPath` leaves the bottom of a node and reaches the top of the next with orthogonal segments. When the next node is not below, it goes through the space between the two nodes, or on the right of both. Curves crossed the cards.
- **Drawing** (`render.js`):
  - rank badge on the top-left corner;
  - an `exec-handle` in the middle of the bottom side of each node of a chain;
  - a `link-mark` path per link for the filled marks. `moveScene` only moves `path.link` and `path.link-hit`, and updates the marks separately: it used to give every path of a link the curve.
  - The label of an assembly includes its mode (`Assembly · chain, in order`, `lib/node_icons.js` `ASSEMBLY_MODES`).
- **Gesture** (`views/canvas/chain_drawing.js`): dragging an `exec-handle` onto a node with the same parent applies `reparentNodes` with the new index, from `lib/chain_order.js` `orderAfter` (pure, tested). The node drag ignores `.exec-handle`, and clicking an execution link opens no panel.
