## Goal

Make the application ready for its first public open-source release under the MIT license: hardened error handling, a clean pip package published on PyPI, CI, complete English documentation and contributor guidelines.

## Scope

In:

  - unhandled promise rejections and JS errors forwarded to the Console;
  - worker and runner crash paths re-checked (plans 08, 17);
  - autosave and recovery re-checked (plan 04) including crash during save (write to a temporary file then atomic rename everywhere files are written);

- Startup review: time to first paint, GEMSEO never imported in the UI process. Guard test: since `conftest.py` imports GEMSEO at collection, the check runs in a subprocess that imports every `gemseo_process_builder.app` and `core` module and asserts `"gemseo" not in sys.modules` (the subprocess must not import `PySide6.QtWebEngineWidgets`, to stay under one second).

## Implementation notes

- **Atomic writes** (`core/atomic_write.py`): every file the application writes (projects, autosave, preferences, run info, surrogate metadata, wrapper descriptors, exports, report, catalog cache, generated scripts) goes through a temporary file and `os.replace`.
- **Unexpected errors** (`app/error_handling.py`): `sys.excepthook` and `threading.excepthook` log the error and show a non-modal message box with "Copy details" (at most three at a time, shown through a queued signal so that other threads never touch Qt). The page logs `error` and `unhandledrejection` events to the console, which is forwarded to the log.
- **Lock file** (`core/project_lock.py`): `<project>.lock` holds the pid, host and time. A lock of a dead process on the same host is ignored (psutil). A project locked elsewhere opens read-only: the title bar and the status bar say so, Save raises `PROJECT_LOCKED` (Save as works), and no autosave is written.
- **Guard test** `tests/python/test_no_gemseo_in_ui.py` imports every UI module in a subprocess and checks that no `gemseo` module is loaded.
- **Licenses**: `tools/third_party_notices.py` generates `THIRD_PARTY_NOTICES.md` from the installed distributions; every license is either confirmed by hand or of an accepted family, else the tool fails. 53 Python dependencies and the vendored d3 and elkjs, all compatible (GEMSEO and PySide6 are LGPL, imported only).
- **Packaging**: `requires-python = ">=3.12,<3.14"`; the wheel carries the notices and vendor licenses. The wheel was installed in a fresh Windows venv and `tools/smoke_installed.py` passed 9/9 examples (Sellar 3.18339 ×3, Rosenbrock DOE 30, parametric 15, DOE around optimization 5, Sobieski -1948.22, external code 1.125, surrogate chain -34.506). Linux is covered by the CI `package` job.
- **CI** (`.github/workflows/check.yml`): Ubuntu and Windows × Python 3.12 and 3.13 run `tools/check.py` (offscreen Qt), then a `package` job builds the wheel and runs the smoke script from a fresh venv. **Release** (`release.yml`): a `v*` tag builds, runs `twine check`, checks the tag against the version, publishes on TestPyPI, then on PyPI through the `pypi` environment (trusted publishing; the environment requires approval).
- **Canvas fix found during the checklist**: fitting a hidden canvas produced NaN transforms; `fit()` now waits until the workflow tab is shown, and `zoomTo` skips transitions without a size.
- **Pending**: the TestPyPI and PyPI publication, which needs the user's confirmation and the trusted publishers configured on both indexes (`testpypi` and `pypi` environments on GitHub).
