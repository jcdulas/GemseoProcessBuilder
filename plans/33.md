# 33 — Robustness, packaging and documentation

Status: Not started
Depends on: 32
SPEC: § 14.2, § 14.3, § 14.4, § 14.5, § 14.6, § 1.3

## Goal

Make the application ready for its first public open-source release under the MIT license: hardened error handling, a clean pip package published on PyPI, CI, complete English documentation and contributor guidelines.

## Scope

In:
- Robustness review:
  - global exception hook in the UI process (logs, non-blocking error dialog with "Copy details");
  - unhandled promise rejections and JS errors forwarded to the Console;
  - worker and runner crash paths re-checked (plans 08, 17);
  - autosave and recovery re-checked (plan 04) including crash during save (write to a temporary file then atomic rename everywhere files are written);
  - project files opened read-only when locked by another instance (lock file next to the project).
- Startup review: time to first paint, GEMSEO never imported in the UI process. Guard test: since `conftest.py` imports GEMSEO at collection, the check runs in a subprocess that imports every `gemseo_process_builder.app` and `core` module and asserts `"gemseo" not in sys.modules` (the subprocess must not import `PySide6.QtWebEngineWidgets`, to stay under one second).
- Packaging:
  - `pyproject.toml` finalized (classifiers including `License :: OSI Approved :: MIT License`, `license = "MIT"`, `license-files`, project URLs, optional extras);
  - `LICENSE`, static files and vendor licenses included in the wheel and the sdist; `THIRD_PARTY_NOTICES.md` generated from the dependency list, with every license confirmed (SPEC § 14.6);
  - build the wheel and sdist, install the wheel in a fresh venv on Windows and Linux, run the smoke checklist;
  - PyPI publication: release workflow triggered by a version tag, using PyPI trusted publishing; first upload to TestPyPI, then PyPI after the user confirms (publishing is public and irreversible).
- CI: the repository is hosted on GitHub (https://github.com/jcdulas/GemseoProcessBuilder), so use GitHub Actions and PyPI trusted publishing. The pipeline runs `python tools/check.py` on Windows and Linux with Python 3.12 (minimum and reference version) and Python 3.13 if GEMSEO 6 supports it, on every push and pull request.
- Open-source project files:
  - `CONTRIBUTING.md`: development setup, completion of plans, the rules of CLAUDE.md (English, one-second tests, readable generated code), inbound = outbound MIT contributions;
  - `CODE_OF_CONDUCT.md` (Contributor Covenant);
  - `SECURITY.md` (how to report a vulnerability privately);
  - issue templates (bug report, feature request) and a pull request template.
- Documentation (English):
  - `README.md` final (install from PyPI, first steps, screenshots, license badge and section);
  - `docs/user_guide.md`: building a model, linking rules (implicit/explicit, namespaces), drivers, running, results, wrappers, surrogates, exports, shortcuts;
  - `docs/developer_guide.md`: architecture, bridge and worker protocols, adding a command, a validation rule, a component kind, a results view; test rules (one-second limit); codegen readability rules;
  - `CHANGELOG.md`.
- Manual end-to-end checklist (`docs/release_checklist.md`) covering every example project, executed on Windows and Linux before release.

Out:
- Hosting a documentation website (the Markdown docs in the repository are enough for the first release).
