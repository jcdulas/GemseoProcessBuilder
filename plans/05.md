# 05 — Commands, undo/redo and document sync

Status: Done
Depends on: 04
SPEC: § 3.5, § 8.2 (undo/redo, copy/paste)

## Goal

Make the Python model editable only through commands, with undo/redo and grouped transactions, and keep a JS mirror of the document up to date through revisioned patches. Add copy/paste of sub-graphs through the system clipboard.

## Scope

In:
- Command framework and the first commands: `addNode`, `deleteNodes`, `renameNode`, `moveNodes`, `reparentNodes`, `setNodeProperties`, `setPorts`, `addLink`, `deleteLinks`, `setLayout` (collapsed state, zoom per level).
- Undo stack bounded by the `max_undo` preference; transactions (`begin`/`commit`) to group commands.
- Revision counter and change lists; `document.patch` / `document.reset` events.
- `store.js`: JS mirror, patch application, subscriptions by entity id and kind.
- Copy/cut/paste/duplicate with the `application/x-gpb-subgraph` MIME type; name collision suffixes.
- Edit menu actions: Undo, Redo, Cut, Copy, Paste, Duplicate, Delete, Select all (selection itself is handled in plan 06; here the actions take ids).

Out:
- Commands for later features (driver config, links semantics, grouping) are added by their plans using this framework.

## Design

- A command is a Pydantic model with a `type` discriminator, so JS can send `{ "type": "moveNodes", "positions": {...} }` directly. `apply(project) -> (Changes, inverse_command)`. Inverses are computed at apply time (store what was removed).
- `Changes` = list of `{ op: "upsert"|"delete", kind, id, data? }`, deduplicated per `(kind, id)`.
- `doc.execute` returns `{ rev }`; the patch goes out as a `document.patch` event, including for undo/redo.
- A command that fails validation raises `CommandError` → bridge error `conflict`; the document is untouched (apply on a copy of the affected sub-tree, or validate before mutating).
- Merge rule: consecutive `moveNodes` on the same ids within 500 ms merge into one undo entry (JS also sends only one per gesture).
- Deleting a node deletes its descendants and the links touching them; undo restores everything including layout.
- Paste: new ids everywhere, names suffixed `_1`, `_2`… on collision, internal links preserved, links to outside nodes dropped.
- JS `store.js`: `store.get(id)`, `store.children(id)`, `store.subscribe(kind|id, fn)`, `store.rev`. On a revision gap it calls `project.get` and emits a reset.

## Implementation notes

- **Commands** (`core/commands.py`): `insertNodes`, `addNode`, `deleteNodes`, `renameNode`, `reparentNodes` (list of `{id, parent, index}` placements), `setNodeProperties` (only `description`, `config`, `mode`, `mda_settings`, `isolated`, `transparent`, `kind`), `setPorts`, `insertLinks`, `addLink`, `deleteLinks`, `moveNodes`, `setLayout`. Each validates everything before mutating and returns an `Effect` (inverse command + touched/removed entity keys). `addNode` generates the id and suffixes the name when taken (`A_1`).
- Undo restores the project **exactly**: deleted links go back to their former positions (`link_indices` / `indices`), and layout entries that did not exist are removed again (`moveNodes` and `setLayout` accept `None` values meaning "remove"). A parametrized test checks apply → undo → redo → undo → redo byte-for-byte for every command.
- **Document** (`core/document.py`): owns the project, the revision, the undo/redo stacks (bounded by `max_undo`), transactions (`begin`/`commit`/`rollback`, `execute_many`), and the merge of consecutive `moveNodes` on the same nodes within 0.5 s. `ProjectSession.project` is now a property backed by `session.document`.
- **Flat entities for the page**: kinds `node` (fields without `children`, plus `parent` and, for containers, the ordered `children` ids), `link`, `layout` (per node id), `level` (per container id), `view` (`tree_expanded`, `extra.<key>`). `doc.snapshot` returns `{rev, root, nodes, links, layout, levels, view, project: {metadata, settings}}`; `document.reset` now sends this snapshot (not the nested project, which stays available through `project.get`).
- Every change marks the project dirty; undoing back to the saved state does not clear the flag (a "clean point" can be added later if wanted).
- **Bridge methods** (`app/api_doc.py`): `doc.snapshot`, `doc.execute {command, undoable}`, `doc.executeMany {commands, label}`, `doc.undo`, `doc.redo`, `doc.undoState`, `doc.copy/cut {ids}`, `doc.paste {parent, x?, y?}`, `doc.duplicate {ids}` (paste results include the new top-level ids). Events: `document.patch {rev, changes}`, `undo.state`.
- **Clipboard**: `application/x-gpb-subgraph` MIME data plus the same JSON as text; the format is tagged `gpb-subgraph/1`. Pasting without a position shifts nodes by 30 px.
- **Page**: `app.store` (`store.js`, pure logic in `lib/patch.js`) mirrors the document, detects revision gaps and reloads the snapshot. Edit › Undo/Redo are wired (enabled from `undo.state`); Cut/Copy/Paste/Duplicate/Delete/Select all need the selection and are wired in plan 06.
- Test helpers to build projects live in `tests/python/builders.py` (pytest `pythonpath` includes `tests/python`).
- Checked in the real application: add, undo, redo, copy, paste with renaming, dirty flag in the status bar, command errors reported as `conflict`.
