# 05 — Commands, undo/redo and document sync

Status: Not started
Depends on: 04
SPEC: § 3.5, § 8.2 (undo/redo, copy/paste)

## Goal

Make the Python model editable only through commands, with undo/redo and grouped transactions, and keep a JS mirror of the document up to date through revisioned patches. Add copy/paste of sub-graphs through the system clipboard.

## Scope

In:
- Command framework and the first commands: `addNode`, `deleteNodes`, `renameNode`, `moveNodes`, `reparentNodes`, `setNodeProperties`, `setPorts`, `addLink`, `deleteLinks`, `setLayout` (collapsed state, zoom per level).
- Undo stack bounded by the `max_undo` preference; transactions (`begin`/`commit`) to group commands.
- Revision counter and change lists; `document.patch` / `document.reset` events.
- `store.js`: JS mirror, patch application, subscriptions by entity id and kind.
- Copy/cut/paste/duplicate with the `application/x-gpb-subgraph` MIME type; name collision suffixes.
- Edit menu actions: Undo, Redo, Cut, Copy, Paste, Duplicate, Delete, Select all (selection itself is handled in plan 06; here the actions take ids).

Out:
- Commands for later features (driver config, links semantics, grouping) are added by their plans using this framework.

## Design

- A command is a Pydantic model with a `type` discriminator, so JS can send `{ "type": "moveNodes", "positions": {...} }` directly. `apply(project) -> (Changes, inverse_command)`. Inverses are computed at apply time (store what was removed).
- `Changes` = list of `{ op: "upsert"|"delete", kind, id, data? }`, deduplicated per `(kind, id)`.
- `doc.execute` returns `{ rev }`; the patch goes out as a `document.patch` event, including for undo/redo.
- A command that fails validation raises `CommandError` → bridge error `conflict`; the document is untouched (apply on a copy of the affected sub-tree, or validate before mutating).
- Merge rule: consecutive `moveNodes` on the same ids within 500 ms merge into one undo entry (JS also sends only one per gesture).
- Deleting a node deletes its descendants and the links touching them; undo restores everything including layout.
- Paste: new ids everywhere, names suffixed `_1`, `_2`… on collision, internal links preserved, links to outside nodes dropped.
- JS `store.js`: `store.get(id)`, `store.children(id)`, `store.subscribe(kind|id, fn)`, `store.rev`. On a revision gap it calls `project.get` and emits a reset.

## Tests

- Each command: apply then inverse restores an identical project (compare `dumps()`).
- Undo/redo sequences, bound respected, redo cleared after a new command, transaction grouping, move merging.
- Failing command leaves the project untouched.
- Clipboard: subgraph with internal and external links, collision renaming, paste into another parent.
- `patch.test.js`: upsert/delete, nested children order, revision gap detection.

## Acceptance criteria

- From the DevTools console, `api.call("doc.execute", {...})` edits the document, `Ctrl+Z` / `Ctrl+Y` undo and redo it, and the store stays consistent.
- `python tools/check.py` passes.
