# 01 — Qt shell and `gpb://` scheme

Status: Not started
Depends on: 00
SPEC: § 3.1, § 3.2, § 1.2 (offline), § 14.2

## Goal

Open a PySide6 window that displays a local HTML page through the custom `gpb://` scheme, with ES modules and vendored d3 working, and no network access. This plan also settles risk #3 of SPEC § 17.

## Scope

In:
- Application entry point, `QApplication` setup, scheme registration, scheme handler.
- Main window with a `QWebEngineView` and a placeholder native menu bar.
- Vendored d3 v7 and elkjs.
- Navigation lock and network restrictions.
- `--dev` flag opening DevTools.

Out:
- QWebChannel bridge (plan 02).
- Real panels and menus content (plan 03).

## Steps

- [ ] Download the latest d3 7.x UMD build (`d3.v7.min.js`) and the latest elkjs `elk.bundled.js` once; commit them with their licenses; record versions in `static/vendor/README.md`.
- [ ] `register_scheme()`: `QWebEngineUrlScheme(b"gpb")` with `SyntaxHost`, flags `SecureScheme | LocalScheme | LocalAccessAllowed | CorsEnabled`; called before `QApplication` is created.
- [ ] `StaticSchemeHandler.requestStarted(job)`:
  - map `gpb://app/<path>` to `gemseo_process_builder/static/<path>` (use `importlib.resources`);
  - reject path traversal (`..`, absolute paths) with `job.fail(QWebEngineUrlRequestJob.Error.UrlInvalid)`;
  - serve `vendor/qwebchannel.js` from the Qt resource `:/qtwebchannel/qwebchannel.js`;
  - set the MIME type from the extension (`.js` → `text/javascript`, `.css`, `.html`, `.svg`, `.json`, `.png`, `.woff2`);
  - return 404-style failure (`UrlNotFound`) for missing files;
  - keep the reply `QBuffer` alive until the job is destroyed (parent it to the job).
- [ ] `AppWebPage.acceptNavigationRequest`: allow only `gpb://app/…`; open nothing else.
- [ ] Web settings: `LocalContentCanAccessRemoteUrls = False`, `LocalContentCanAccessFileUrls = False`; install a `QWebEngineUrlRequestInterceptor` on the profile that blocks every `http`, `https`, `ws`, `wss` and `file` request and logs it.
- [ ] Use a dedicated off-the-record `QWebEngineProfile` so no browser data is written to disk.
- [ ] `MainWindow`: title "GEMSEO Process Builder", default size 1400×900, placeholder menus File / Edit / View / Model / Run / Tools / Help (File › Quit works).
- [ ] `--dev`: open a second window with `page.setDevToolsPage()`.
- [ ] `index.html`: loads `vendor/d3.v7.min.js` and `vendor/elk.bundled.js` with classic scripts, then `js/main.js` as a module. `main.js` imports `lib/hello.js` and draws an SVG with a circle and the text returned by `hello.js`.
- [ ] Manual check on Windows (and on Linux if available): the SVG shows, the DevTools console has no error, a `fetch("https://example.com")` typed in DevTools is blocked.

## Tests

- `test_scheme_handler.py`: test the path mapping and MIME function as plain functions (extract them from the handler so no `QWebEngineUrlRequestJob` is needed): valid path, traversal attempt, missing file, qwebchannel special case, MIME types.
- `hello.test.js`: tests the pure function of `lib/hello.js`.

## Acceptance criteria

- `python -m gemseo_process_builder` shows the page with the d3 SVG, offline.
- ES module import works through `gpb://`. If it does not on one platform, switch to classic scripts, record it in the notes and update SPEC § 3.2 and § 17.
- `python tools/check.py` passes.
