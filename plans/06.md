# 06 — Workflow canvas core

Status: Done
Depends on: 05
SPEC: § 8.2 (navigation, node rendering, editing), § 14.1 (render only the current level)

## Goal

Render the document as an SVG flow diagram with d3 and support the basic editing gestures: navigation in the hierarchy, zoom/pan, selection, move, delete, context menu. Links are drawn from the stored explicit links only; coupling semantics arrive in plans 11–12.

## Scope

In:
- Rendering of the **current level**: components, assemblies and drivers as boxes/containers, ports, explicit links as Bézier curves.
- Breadcrumb navigation (double-click to enter, `Backspace` / `Alt+↑` to go up), expand a container in place.
- `d3.zoom` pan/zoom, "Fit to view", zoom to selection; zoom state per level stored in the layout.
- Selection model (click, Ctrl+click, rectangle, `Ctrl+A`, `Esc`), shared with other panels through a small selection service.
- Moving nodes (one `moveNodes` command per gesture), delete, rename (inline editor on F2 / double-click on the name), context menu framework.
- Port display mode per node: `all | connected | none`, with a hidden-port counter.
- Temporary "Add" menu on the canvas background (Assembly, Component placeholder, drivers) until the library exists (plan 09).

Out:
- Library drag and drop (plan 09), link drawing (plan 12), coupling display (plan 12), minimap, search and auto-layout (plan 26), execution status colors (plan 18).

## Design

- The SVG has layers: `g.links`, `g.nodes`, `g.overlay` (selection rectangle, ghosts). One `g.node` per node keyed by id (`selection.data(nodes, d => d.id)`), updated incrementally on store changes.
- Node geometry is computed in `lib/geometry.js` from port counts and display mode, so it is testable and reused later by the minimap and layout.
- Header colors per node type come from CSS tokens (defined in plan 03). Container nodes show their children only when expanded in place; entering a container re-renders the canvas at that level.
- Drag: positions are updated locally on every mouse move; on drag end one `moveNodes` command is sent. On command error, positions revert from the store.
- New nodes without a layout entry get a position next to the last added node; real auto-layout comes in plan 26.
- Keyboard: `Del`, `F2`, `Ctrl+A`, `Esc`, `F` (fit), `Backspace` / `Alt+↑`.

## Implementation notes

- **Scene** (`lib/scene.js`, pure and tested): builds what a level shows — its nodes, the children of containers expanded in place (recursively, up to 6 levels), and the explicit links. A link whose endpoint is hidden inside a collapsed container is drawn to that container. Each item carries its absolute position and its `local` position (the one stored in the layout, relative to its container).
- `NodeLayout.collapsed` was replaced by **`expanded`** (default `false`): containers are drawn collapsed unless expanded in place. The schema version did not change (no file used the old field).
- **Interactions**: wheel zooms; the middle button or Space + drag pans; a left drag on the background draws a selection rectangle (Ctrl adds to the selection); clicking and dragging nodes selects and moves them (one `moveNodes` command per gesture, positions overridden locally during the drag); double-click on a container opens it, on a component or a title renames it in place; Escape clears the selection.
- **View state without undo**: zoom/pan per level (`levels`, saved 600 ms after the last change), `expanded` and `port_display` go through `setLayout` with `undoable: false`. They still mark the project as modified.
- **Actions wired to the selection** (`views/canvas/workflow.js`): Delete, Rename (new action `edit.rename`, F2), Select all, Cut, Copy, Paste (at the last pointer position in the current level), Duplicate (the new nodes are selected), Fit (F), Up (Alt+↑ / Backspace). Enabled states follow the selection and the level.
- **Context menus** (`components/context_menu.js`, with submenus): node menu (Open, Expand in place/Collapse, Show variables All/Connected/None, Rename, Duplicate, Cut, Copy, Delete) and background menu (temporary "Add" submenu with Assembly, the four drivers and an Analytic component, Paste, Select all, Fit, Up). The "Add" submenu is replaced by the library in plan 09.
- Nodes without a stored position are shown on a grid but their position is not stored until they are moved; they may overlap other nodes until auto-layout (plan 26).
- Page services added: `app.selection`, `app.navigation`, `app.canvas`.
- Checked in the real application with the Sellar fixture: levels and breadcrumb, ports and links, a simulated mouse drag stored the new position, Delete then Undo restored the node, expanding the optimizer in place showed its children and their link.
