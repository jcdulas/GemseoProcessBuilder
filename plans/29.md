# 29 — Executable wrapper editor

Status: Done
Depends on: 28
SPEC: § 7.5 (graphical editor, test run, reusable descriptor)

## Goal

Let users wrap an external code graphically: mark input values in a sample input file, select output values in a sample output file, test the wrapper, and save it as a reusable descriptor.

## Scope

In:
- Wrapper editor opened full-panel from an `executable` component (inspector button "Open wrapper editor") or from `Tools › New executable wrapper…`. Tabs:
  1. **Command**: executable picker, arguments with token insertion, environment variables, timeout, working directory policy, files to copy.
  2. **Inputs**: load a sample input file; text view with line numbers; selecting a number (or a range for a vector) → "Make variable" (name, format guessed from the selected text, unit, description) → the text is replaced by a highlighted `{{name:format}}` marker; list of markers with edit/delete; several input files supported.
  3. **Outputs**: load a sample output file; selecting a value → proposes a rule (marker-based by default, regex as an alternative) with a live preview of the extracted value on the sample; table rule from a selected block; list of rules with preview status.
  4. **Test run**: fill input values (defaults from the sample), run the wrapper in the worker, show extracted outputs, stdout/stderr, return code, working directory (with "Open folder").
- Ports of the component updated from the markers and rules (through `setPorts` in the same transaction as the config change).
- Save as descriptor (`.gpbwrap.json`) into a catalog folder; "Detach from descriptor" to edit an inline copy.
- Worker method `executable.test_run(spec, inputs)`.

Out:
- Nothing else; this completes § 7.5.

## Deliverables


## Design

- The text views are plain `<pre>` elements with spans for markers; files up to 5 MB are loaded, larger files show only the first 5 MB with a warning.
- Rule suggestion prefers the closest preceding text on the same line as the marker; regex suggestions escape literal text and capture a number pattern.

## Implementation notes

- Runtime:
  - `TemplateFile.content` holds a template inline (wrappers kept in a project); `template` names a file otherwise.
  - `ExecutableDiscipline.last_run` keeps the command, return code and output of the last run, for the test run report.
  - `spec_ports(spec)` (pure) gives the ports of a wrapper; the worker introspection and the app both use it.
- App `app/api_executable.py` (no GEMSEO in the UI process):
  - `executable.loadDescriptor`: the spec with its templates inline and its files absolute, plus the descriptor folder.
  - `executable.saveDescriptor`: inline templates become `<target>.tmpl` files next to the descriptor; paths are made relative to it (absolute across drives); the `.gpbwrap.json` suffix is added when missing.
  - `executable.preview` reads a rule on a sample with `runtime/parsing.py`, so previews match runs exactly.
  - `executable.readSample`: at most 5 MB (`truncated` flag, the editor warns), universal newlines like the wrapper itself.
  - `executable.apply` sets the configuration (`descriptor_path`, or `spec` + `base_folder_path`) and the merged ports in one undo step (`setNodeProperties` + `setPorts`); introspection then confirms the ports.
  - `executable.add` adds a component running a wrapper, with its ports; `executable.reveal` opens a working folder; `executable.testRun` calls the worker.
- Worker `executable.test_run(spec, inputs, base_folder)`: retention "always", working folders in the temporary folder unless set; returns the outputs, error, command, return code, stdout/stderr (last 20 000 characters) and the working folder.
- Pure libraries (node tests):
  - `lib/number_selection.js`: number tokens (Fortran D exponents, signs, not the digits inside words), format guessing (`.6e`, `.1E`, `12.4f` when leading spaces are selected, `.0f` for integers), vectors and their separator, markers (`templateMarkers`, `renameMarkers`, `replaceByMarker`), and `formatNumber` writing values back like Python when a marker is removed.
  - `lib/rule_suggestion.js`: `key_value` (`=` or `:`; only when the value ends the line), `marker` on the same line or on a label line up to 3 lines above, escaped `regex` (first and last match), and `table` from a selection over several lines (header lines as `skip`, the next line as `end` when not empty). The editor previews each suggestion and only offers those reading the selected value.
- Editor `views/wrapper_editor/` (center tab, one per component, `Tools › New executable wrapper…`, inspector button "Open wrapper editor"):
  - `text_view.js`: `<pre>` with line numbers, highlighted markers, selection as text offsets; a click selects the number under it.
  - `command_tab.js`: name, command line with token buttons and an executable picker, input/output files, timeout, success codes, error patterns, environment variables, working folder root and retention, files and folders to copy.
  - `inputs_tab.js`: several input files; load a sample, select a value or a vector, "Make variable" (name, format, unit, description) replaces it by `{{name:format}}`; markers of unknown inputs are shown in red; renaming an input renames its markers; "Remove marker" writes the default value back; an "Edit text" mode.
  - `outputs_tab.js`: output samples by file (renamable, `stdout` too); suggestions with a guessed output name; outputs table with each rule and the value it reads in the sample; a field-by-field rule editor with live preview; file outputs.
  - `test_run_tab.js`: input values (defaults from the sample), run, outputs, error, command, return code, working folder with "Open folder", stdout/stderr; the standard output or the output files of the run can become samples.
  - Header actions: "Apply to component", "Add to model" (new wrapper), "Save descriptor" / "Detach from descriptor" (component using a descriptor), "Save as descriptor…" (starts in the first catalog folder, refreshes the catalog, offers to make the component use the new descriptor), "Open descriptor…".
- Tests: app methods (load/save round trip, relative paths, previews of every rule kind, apply and undo in one step, add), worker test runs (success, failure with its output, invalid spec), node tests of both libraries.

Selections and the "Make variable" / "Add output" buttons were driven through the editor's DOM; the file dialogs were bypassed with direct `executable.readSample` / `executable.saveDescriptor` calls.
  - The markers came out as `{{x:.12e}}` and `{{y:.12e}}`, and the output rules as `key_value` on `output.txt`.
  - The test run gave f = 1.5 and g = -0.5 at the sample values.
  - Once applied and saved as a descriptor used by the component, the optimization run reached f = 1.125 at (0.75, 1.75), the same optimum as plan 28.
