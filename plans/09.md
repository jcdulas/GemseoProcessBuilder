# 09 — Component catalog and library panel

Status: Done
Depends on: 07, 08
SPEC: § 7.6

## Goal

Discover reusable components in configured folders (inside the worker), cache the result, and show them with the built-in items in the Library panel, from which they are dragged onto the canvas or the tree.

## Scope

In:
- `runtime.component` decorator (units, description, icon metadata).
- Worker method `catalog.scan(paths)`: finds `Discipline` subclasses **defined** in each `*.py` module, decorated functions, and `*.gpbwrap.json` descriptors (only listed here; their content is used in plan 28).
- Import isolation per module: an import error is captured with its traceback and does not stop the scan.
- Cache keyed by (absolute path, mtime) in the user cache dir; incremental rescan.
- Catalog paths from global preferences and project settings.
- `QFileSystemWatcher` on catalog folders with a 1 s debounced rescan.
- Library panel: Built-in section (Analytic, Python function, Python class, Executable wrapper, Surrogate, Assembly, drivers MDA / DOE / Optimization / Parametric) and one section per folder (tree by sub-folder and module), search box, error badges.
- Drag and drop from the library to the canvas (at the drop position, in the current level) and to the tree (into a container); the created node carries the catalog reference in its `config`.
- Remove the temporary "Add" menu of plan 06 (keep it in the canvas context menu, fed by the catalog).

Out:
- Computing ports of the dropped component (plan 10). Nodes created here have no ports until introspection runs.

## Design

- A module is imported under a unique synthetic name derived from its path, with its folder temporarily added to `sys.path` so relative imports of sibling modules work.
- "Defined in the module" means `cls.__module__ == module.__name__`.
- Discipline classes that are abstract or require constructor arguments without defaults are still listed; their `init_args` form comes in plan 10.
- Entry reference format: `{ "module_path": "<abs path or dotted module>", "attribute": "ClassOrFunction" }`. Installed packages can also be referenced by dotted module (e.g. `gemseo.problems.mdo.sellar.sellar_1`).
- The scan runs in the worker; the UI shows a spinner in the Library while it runs.

## Implementation notes

- **Scanner** (`catalog/scanner.py`, runs in the worker as `catalog.scan {files}`): finds `Discipline` subclasses defined in each module (imported classes are ignored), functions marked with `gemseo_process_builder.runtime.component(units=…, description=…, icon=…)`, and `*.gpbwrap.json` descriptors. Each module is imported under a unique name derived from its path and mtime, with its folder temporarily on `sys.path` (sibling imports work). Any exception, including `SystemExit`, is reported for that file with its traceback. `__pycache__`, hidden folders and virtual environments are skipped.
- **Service** (`app/catalog_service.py`): folders = preferences `catalog_paths` then project `settings.catalog_paths`; files listed in the UI process, only new or changed files (by mtime) are sent to the worker, from a pool thread; results cached in `<cache dir>/catalog_cache.json`; folders watched with `QFileSystemWatcher` and rescanned 1 s after a change; rescans also when GEMSEO is loaded, when the folders change (preferences or project), and on Refresh (`catalog.refresh` forces a full scan). Event `catalog.updated {scanning, folders: [{path, exists, files: [{relative, entries, error}]}], errors}`.
- **Library panel**: built-in items (`lib/builtins.js`, also used by the canvas "Add" menu) and one section per folder, search, error rows opening the traceback. Items are dragged onto the canvas (at the drop point, current level) or onto a container of the tree, or double-clicked (center of the canvas). Nodes from the catalog: `python_class` → `config {module_path, class, init_args}`, `python_function` → `config {module_path, function}`, `executable` → `config {descriptor_path}`.
- **Project settings**: new command `setProjectSettings {metadata, settings}` (undoable) and a new entity kind `project` (`metadata`, `settings`) in patches; Model › Project settings dialog (name, description, catalog folders, runs folder). Global catalog folders are edited in Tools › Preferences. The session now notifies listeners on every content change (so the window title follows the project name).
- **Two worker bugs found in the real application and fixed**:
  1. running the worker with `python -m` executes its module as `__main__`; worker methods importing `require_gemseo` by name got a second copy of the module whose "GEMSEO loaded" flag was never set, so the first catalog scan waited 120 s. The GEMSEO loading state moved to `workers/gemseo_loader.py`.
  2. on Windows, a DLL loaded while the request reader thread waits on the stdin pipe hangs when its initialization queries the standard input handle. `protected_stdin()` now points fd 0 and the Windows standard input handle (`SetStdHandle`) to `NUL`; only the private duplicate reads the pipe.
- The catalog is scanned only after GEMSEO is loaded (a cold GEMSEO import can take 5–10 s on this machine).
