# 44 — Large NumPy arrays

Status: Done
Depends on: 43
SPEC: § 6.4, § 7.3

## Goal

"Are NumPy variables handled well? Many NumPy arrays will go through." Measured on a generated class with an input of 100,000 elements:

- the class held 100,000 numbers written out (0.5 MB of unreadable code), and so did the project (the default of the port);
- the JSON grammar made from names refused a 3×4 output, and checked the data in 10 to 34 ms per execution, against 0.1 to 1 ms for GEMSEO's simple grammar.

The user chose four corrections: the fast grammar, compact default values, a light project and a fast mode for runs.

## Scope

In:
- `core/discipline_file.py`:
  - inputs with a shape, a type and a default value (every element, or one filling the array), written `array([…])` or `full(shape, value)`;
  - the simple grammar in the class;
  - the files of plan 43 still read;
- the worker keeps the defaults of more than 1,000 elements out of the ports;
- `Execution.validate_data`: in the script (`configure(...)` in `main`), in the mapping and in the runner;
- page: the Shape and Type of the inputs; the fast mode in the Execution tab.

Out:
- Shapes of outputs declared in the class (they are known after a run).

- A DOE of 200 samples on it gives the same results checked (0.28 s) and in fast mode (0.05 s).
- `python tools/check.py` passes.

## Implementation notes

- **Grammar**:
  - `default_grammar_type = Discipline.GrammarType.SIMPLE`, then `update_from_data(INPUTS)` and `update_from_types(dict.fromkeys(OUTPUTS, ndarray))`.
  - It checks that each value is an array, not its shape: a Python float given as input is still refused.
- **Readability**:
  - At most 20 values are written one by one; beyond, one value fills the array and the code computes the others.
  - Sizes of 10,000 and more get underscores (`100_000`).
- **Plan 43 files**: their list defaults are still read. A rewrite changes only the block, and imports `full` when needed. Their `__init__` keeps the JSON grammar: recreate the file to get the simple one.
- **`configure`** sets every option of GEMSEO at once. The runner therefore sets `enable_discipline_status` and the validation together; the script's `main` turns the validation off when run on its own.
- **Large defaults**: a port without its default still has its shape and type. A design variable made from it gets no initial value: type one filling the vector.
