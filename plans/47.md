## Goal

The script becomes the project: saving writes a GEMSEO script that reads like one written by hand, with what only the interface needs in a hidden side file; the code the user adds to the script is kept (the user's choices, plan 46).

## Scope

In:
- `core/script_project.py`: merging the generated script with the previous file, the side file, the carry-over of ids and layout;
- `codegen`: the script of a whole project, using its own definitions;
- `ProjectSession`: saving as a script, opening from a side file, adopting a script as the project file;
- `ProjectController`: opening a `.py` from its side file or by reading it;
- the save dialog (a script by default), the notes shown after a save.

Out:
- Keeping explicit links between differently named variables when a changed script is read again (they come back only from an unchanged side file).

## Implementation notes

- **Fingerprint**: SHA-256 of the script with `\r\n` turned into `\n`, so that an editor changing line endings does not make the script look edited.
- **Kept code**:
  - It is placed after the imports and before the first function of the application.
  - Comments right above a kept definition go with it.
  - An import of the file is kept unless its lines are already in the generated script.
  - Folder constants (`*_FOLDER = Path(…)`) are the application's.
- **Hidden side file on Windows**: a hidden file cannot be replaced, so it is made normal for the write and hidden again after it.
- **Incomplete projects**: a code generation error does not prevent saving. The side file then holds the fingerprint of the script left as it is, so the project opens again from it.
- **Save dialog**: a GEMSEO script by default (`*.py`), the project format as the second filter; the suffix follows the chosen filter.
- A project read from a script has that script as its file: *Save* writes it back.
