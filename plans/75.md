# 75 — Catalog entries from installed packages

Status: To do

SPEC: § 3.4, 4.2, 4.2.1, 7.6, 9.1, 10.1, 14.5, 15.2, 17 (open point 10); [SIZING_LOOP_EVOLUTIONS.md](../docs/SIZING_LOOP_EVOLUTIONS.md) § 2 (GPB-E1)

## Goal

An installed package gives its disciplines and functions to the Library through the entry-point group `gemseo_process_builder.components`, with their descriptions and units, without a catalog folder and without depending on the application; the generated script imports them as a developer would (`from gemseo_nastran.sizing import StructuralSizing`). First user: `gemseo_nastran`. Milestone M3 of the sizing loop (ECOSYSTEM-EVOLUTIONS.md § 6).

## Scope

In:
- the owner's confirmation of the name of the group (SPEC § 17, open point 10), before any code;
- worker method `catalog.packages`: the discovery of SPEC § 7.6 (entry points listed with their distribution, importing nothing; declarations loaded; keys checked, unknown keys warned; each `module` located with `importlib.util.find_spec`, not imported); one error per package, with its traceback;
- the catalog cache keyed by (distribution name, version), plus the modification time of the declaration file for an editable install (PEP 610 `direct_url.json`); **Refresh** reloads every package;
- `catalog.list` and the event `catalog.updated` carry the packages;
- Library: one section per package after the folders ("gemseo-nastran 0.3.0"), its entries grouped by `group`; search, error rows and drag and drop as for folder entries;
- a placed component keeps its dotted `module`, its class or function and `package {name, version}` in its `config`; introspection imports the module (§ 7.3);
- codegen: one `from <module> import <attribute>` line, no `sys.path`;
- script reader: a discipline whose module belongs to a declared package records that package;
- validation: the package missing from the Python of the runs (Error), another version (Info).

Out:
- the declaration of `gemseo_nastran` (its own specification);
- `gemseo_plugins` (GEMSEO's registration, which the application does not need);
- executable descriptors and surrogates given by packages.

## Tests

- A fake distribution written in a temporary folder (a `*.dist-info` with `entry_points.txt` and `METADATA`, a package with its declaration) on the `sys.path` of the worker under test: entries found with their distribution name and version; a second scan of the same version imports nothing (the declaration module absent from `sys.modules`); a new version, or an edited editable install, is loaded again.
- A declaration raising at import, a missing `module`, a key of the wrong type: one error each, the other packages still listed.
- Golden script: a component from a package is one `from ... import ...` line, without `sys.path`; the script reader records the package.
- Validation: package missing, another version.
- `node --test`: the sections and groups of the Library from a list of packages.
- Every test under one second.

## Acceptance criteria

- A small package declaring entries, installed in the Python of the runs, shows its section in the Library; a study built from its entries runs from the UI and as a standalone script.
- The same with `gemseo_nastran`, when it is available.
- `python tools/check.py` passes.
