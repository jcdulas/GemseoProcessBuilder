# 41 — Guidance in the editors

Status: Done
Depends on: 40
SPEC: § 6.4, § 7.1

## Goal

The user could not find how to set up a DOE, its variables and its responses, nor how to type a formula in an Analytic component. The inputs lacked tips and suggestions.

## Scope

In:
- the steps to set up a driver, at the top of its editor (`lib/driver_checklist.js`, `panels/driver_editor/checklist.js`);
- pickers explaining why they offer nothing;
- the formula editor:
  - examples;
  - completion;
  - functions, operators and variables to insert;
  - detected inputs and outputs;
  - reserved names (`lib/formula_help.js`);
- the worker refusing every SymPy name as a variable.

Out:
- A tour of the whole interface for first-time users.

## Tests

- node:

## Acceptance criteria

- A new DOE shows its three steps, with buttons putting a component inside it and opening its tabs.
- A new Analytic component shows examples; typing `sp` offers `span` when another component has it.
- `python tools/check.py` passes.

## Implementation notes

- **SymPy names**:
  - The old rule refused only `S`, `N`, `E`, `I`, `O` and `Q`. Tried one by one, many more names failed in `AnalyticDiscipline`: `beta`, `gamma`, `zeta`, `test`, `re`, `ln`, `lambda`… Some fail only at execution; `E` and `I` silently become numbers.
  - The worker now refuses every name of the `sympy` module and every Python keyword used as a variable; `pi` stays the number π.
  - The page flags a fixed list of common names while typing: it has no SymPy.
- **Variables used by completion**: the ports of the other components of the project (their `local_name`), without the reserved names.
- **Steps**:
  - The algorithm step is always done: GEMSEO has a default (LHS, SLSQP). It shows the method and the number of samples.
  - *Choose a component…* uses the same command as drawing a link from the driver to a node (`driveNode`).
- **Layout**: the formulas take the whole width of the inspector, their hint above them.
