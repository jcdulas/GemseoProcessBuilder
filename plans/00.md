- `python tools/check.py` passes on a fresh clone after following the README.

- `python -m gemseo_process_builder` prints the version.

## Implementation notes

- Installed versions (Python 3.12.5): GEMSEO 6.3.3, PySide6 6.11.2, Pydantic 2.11.9, numpy 2.3.3, pint 0.26.1, psutil 7.2.2, pytest 9.1.1, ruff 0.16.8, mypy 2.3.1.
- Node 22 does not accept a directory as `--test` argument: the JS test command uses the glob `"tests/js/**/*.test.js"` everywhere (`tools/check.py`, `package.json`, `CLAUDE.md`). Test files must end with `.test.js`.
- The package version is single-sourced in `gemseo_process_builder/__init__.py` (`dynamic = ["version"]` with hatch).
- Added `gemseo_process_builder/py.typed` (typed package).
- isort style: `force-single-line = true` (one import per line, as in SPEC § 10.3); generated scripts follow the same style.
- mypy strict runs without any `ignore_missing_imports`: GEMSEO and PySide6 ship type information.
- pytest filters the `DeprecationWarning`s emitted by matplotlib (pulled in by GEMSEO) about old pyparsing names.
- The collection phase (GEMSEO + PySide6 imports, QApplication) takes a few seconds; the tests themselves are well under one second. The one-second timeout was checked manually on the skipped 1.5 s test: pytest-timeout fails it.
