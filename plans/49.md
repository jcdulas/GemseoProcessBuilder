# 49 — Hidden data of projects

Status: Done
Depends on: 48
SPEC: § 4.2.3, § 12.1, § 14.2

## Goal

Next to its script, the user only sees the script. The runs (with their snapshots), the surrogates, the autosave and the lock of a project are kept in the user data directory of the application, one folder per project file, out of sight (the user's request).

## Scope

In:
- `core/project_storage.py`: the folder of a project file, its origin, moving folders, removing an emptied folder;
- the lock taking a lock file; the session's storage, autosave and lock in it;
- the run and surrogate stores in the storage, with absolute paths;
- *Save as…* moving runs and surrogates to the new storage, surrogate components updated;
- runs and surrogates of earlier versions, next to the file, moved into the storage when a script is opened.

Out:
- Finding the data again after a script was moved outside the application.
- Removing the data of projects whose file no longer exists.

## Implementation notes

- **Root**: the folder of the untitled autosave, `QStandardPaths.AppDataLocation`; `ProjectSession` takes no new argument.
- **Key**: the first 12 hex digits of the SHA-256 of the normalized absolute path of the file, after its name: `projects/sellar-32b2587230aa/`. An untitled project uses `projects/untitled/`, whose runs follow it on its first save.
- **Paths** of runs and surrogates are absolute in memory; older projects referring to runs next to them keep working until they are saved as a script, which moves them.
- **Moves** skip what is in use (a run in progress), which then keeps its old path. When surrogate components change path during a save, the page receives the document again.
- **Opening a script** with runs or surrogates next to it moves them; if a component uses a moved model, the project is marked modified and the user told to save, so that the script points to the new place.
- **Lock**: per user, since the data folder is; two users sharing a folder are no longer warned.
- Surrogate components are written in the script with the absolute path of their model in the storage: such a script runs on this machine only.
