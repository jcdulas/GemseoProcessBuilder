# 17 — Runner and run manager

Status: Not started
Depends on: 16
SPEC: § 11.1, § 11.2, § 11.3, § 11.4, § 12.1 (run folder), § 17 (risk 2)

## Goal

Execute a driver from the UI in a separate process that runs the generated script, streams structured events, and can be stopped cleanly or killed.

## Scope

In:
- Runner entry point `python -m gemseo_process_builder.runner <run_dir>`: loads `script.py` and `script.gpb-map.json` from the run folder, calls `build_scenario()` (or `build_mda()`), attaches instrumentation, executes, saves outputs, emits `finished`.
- Event channel on the protected stdout (reuse `workers/protocol.EventChannel`), commands on stdin (`stop`).
- Instrumentation:
  - `Database` new-iteration listener → `iteration` (optimization) or `sample` (DOE) + `progress`;
  - discipline execution status → `status { node_id, state }`: first check GEMSEO 6's status observation API; fall back to wrapping `execute` on each discipline instance; record which one was used;
  - logging handler → `log` events;
  - rate limiting (20 messages/s per type, aggregation beyond).
- Stop protocol: `stop` on stdin → a flag checked in the listeners → raise a `RunStopped` exception → partial history saved → `finished { state: "stopped" }`. After `stop_timeout_s` without `finished`, the UI kills the process tree with psutil.
- Run manager in the UI process:
  - launch sequence of § 11.1 (validation, project snapshot, script generation, dry run, `QProcess` start);
  - run folder creation `<project>.runs/<run_id>/` with `run.json` (status updated at each stage), `project.gpb.json`, `script.py`, `script.gpb-map.json`, `run.log`;
  - one run at a time unless the preference allows concurrency;
  - lock of the running driver's configuration (commands touching it are rejected with a clear message);
  - bridge methods `run.start`, `run.stop`, events `run.started`, `run.event`, `run.log`, `run.finished`.
- Toolbar and Run menu actions (Run F5, Stop Shift+F5) enabled with proper states.

Out:
- UI monitoring widgets (plan 18), results reading and Runs panel (plan 19).

## Design

- Run ids: `r-YYYYMMDD-HHMMSS[-n]`.
- Contract with the generated script (SPEC § 10.1, plan 16): the runner imports the module, calls `build_scenario()`, attaches its instrumentation, calls `execute_scenario(scenario)`, then saves `history.h5` and `dataset.csv` itself into the run folder. It never calls `main()`.
- Killing: `psutil.Process(pid).children(recursive=True)` then terminate/kill, on Windows and Linux.
- `run.json` statuses: `preparing | running | completed | stopped | failed | killed`.
