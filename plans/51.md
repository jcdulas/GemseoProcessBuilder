# 51 — Choosing the data of a moved script

Status: Done
Depends on: 50
SPEC: § 4.2.3

## Goal

When several moved projects could be the script being opened, the user chooses the one holding its runs and surrogates, instead of none being taken (the user's request).

## Scope

In:
- `Dialogs.ask_project_data`: the list of the candidates, and "None of them";
- a description of each candidate: the old place of its script, its numbers of runs and surrogates, when it was last opened;
- the controller asking when the search is ambiguous.

Out:
- Merging the data of several folders.

## Steps

- [x] `describe` in `core/project_storage.py`.
- [x] The dialog (Qt, unattended) and the controller.
- [x] Tests, SPEC, guide, changelog.

## Tests

- pytest: two moved projects matching the same script: the user is asked with both descriptions; none chosen leaves them apart with a warning; the one chosen follows the script.

## Acceptance criteria

- `python tools/check.py` passes.

## Implementation notes

- The Qt dialog is a `QInputDialog` list; the candidates come in the order of their folder names, and the descriptions tell them apart by the old place of their script.
- The benchmark mode never chooses: no data is taken, as before.
- "Last opened" is the date of `project.json`, written at each save and each opening.
