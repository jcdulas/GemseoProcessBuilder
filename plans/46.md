## Goal

"Projects are saved in the GEMSEO Process Builder format: can we do without it? Hand-written GEMSEO projects should load without any particular action, and the projects we generate should look like them."

The user chose that the script becomes the project, its interface data in a hidden side file, and that the free code of a script is kept when it is saved. This plan reads scripts into projects; plan 47 makes the script the project file.

## Scope

In:
- `workers/script_reader.py`:
  - running a script while recording how its study is built;
  - converting the objects into a project;
  - importing a script for a component without running its study;
- `app/script_opening.py`, *Open project…* on a `.py` file, `ProjectSession.adopt`;
- the page messages;
- the typed values kept by `merge_ports`.

Out:
- Saving a project as a script (plan 47).

## Implementation notes

- **Recording**:
  - A scenario is not a discipline in GEMSEO 6 (it is a `BaseMonitoredProcess`): both classes get the recording `__new__`.
  - It stays installed once for all in the worker: a `__new__` set on a class and removed afterwards breaks it (CPython then passes the constructor arguments to `object.__new__`). Outside a reading it is exactly `object.__new__`.
- **Stopping**: `StudyStopped` is a `BaseException`, so an `except Exception` in a script does not catch it. Disciplines executed after a scenario was created (initial values) run normally; before any scenario, the first one stops the script.
- **Paths**: the script runs in its folder; its path is made absolute first. A function or class of the script (module `__main__`) points to the script itself.
- **Typed values**: the defaults of each discipline when the script stops, compared with those of the same discipline built again with the recorded arguments.
- **`merge_ports`** kept a typed value only when the introspected port had no default: a value typed on a function with default arguments was lost on the next introspection. A typed value now always wins.
- **Introspection**: a project read from a script has ports with its typed values only; `ProjectSession.ports_unknown` makes the component service read every component again.
- **Round trip**: the 12 examples give the same results: Sellar MDF, IDF and DisciplinaryOpt, Sobieski BiLevel, the DOE around an optimization, the sequence, the beam, the wing, the parametric study, the surrogate and the external code.
