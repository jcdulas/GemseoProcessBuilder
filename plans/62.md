## Goal

The user talks with the copilot: asks questions about a run while it goes on or after it, asks Claude to review a driver before running it, and gets, at the end of a piloted run, a short analysis written by Claude, kept with the run and offered in the report of the application.

## Scope

In, in the plugin:
- `pilot.py`: the `copilot.ask` command, answered at the next iteration boundary (or between segments); the post-run report, `report.md` next to the journal;
- `advisor.py`, `context.py`, prompts: the `question` and `report` triggers; a report is text, read tools only;
- `session.py`: the copilot process, `python -m gemseo_claude_pilot.session`, one JSON request on its input, one JSON answer on its output: `ask` (a question on a finished run, from `history.h5` and the journal) and `review` (a driver before its run, from its generated script).

In, in the application:
- bridge: `copilot.ask(run_id, question)` (to the runner while the run goes on, else to the copilot process) and `copilot.review(driver_id)`;
- the copilot process run with the interpreter and the environment of the runs, never in the UI process;
- the Copilot view: a question box, the answers, the report; the Copilot tab: *Review with Claude*;
- the report of the application: the analysis of the copilot of each run shown, when it has one.

Out:
- DOE, BiLevel and surrogates (plan 63).

## Implementation notes

- **Questions during the run**: the `copilot.ask` command queues a question; at the next iteration boundary it goes to the advisor with the `question` trigger (before any periodic check), between segments and while waiting for an answer it is asked at once, and the last ones are answered before the report. The answer is published as a `copilot.message` of kind `answer` with its question; a decision it carries is handled as any other (proposal, or applied in Pilot mode).
- **Report**: a call with the `report` trigger after the end, with the read tools only; `report.md` next to the journal; `result.report`; the summary says whether there is one. It counts in the budget.
- **Copilot process**: `session.py`, run by the UI process with the interpreter and the environment of the runs (`copilot.ask` for a finished run, `copilot.review`), in a background thread of the bridge, 600 s at most. A finished run is read back with `OptimizationProblem.from_hdf`; its algorithm, settings, budget and data level come from the journal (else `run.json` and the preferences). A review imports the generated script from a temporary folder and calls its `build_scenario()` only. Claude only reads: no `submit_decision` is offered.
- **Found on the way**: the past decisions sent to Claude lost the kind of their action (`model_dump(exclude_defaults=True)` drops it, being the default of each action class): Claude did not know what had been done. Fixed. The sizes of the variables of a problem read from `history.h5` are NumPy integers: converted, for JSON.
- **Report of the application**: an option `copilot` (on by default) adds the analysis of each selected piloted run under its results; a small Markdown converter (`report/markdown.py`: headings, lists, tables, bold, code; everything escaped) turns it into HTML. Claude writes tables in its reports: they are supported.
- **By hand, with Claude Code (Max)**: a piloted Sellar MDF run in Advisor mode by the real runner: start review, a proposal to stop once converged, accepted by command, then the report (a summary, a table of the result, the segment, how much to trust it); a question on the finished run through the copilot process (the active constraint and its multiplier, estimated from the last iterates: close to 1); a review of the generated script before its run. The page (question box, report in the Copilot view, *Review with Claude*, the report option) was not exercised in the running application.
- **Tests of the application**: `copilot.ask` and `copilot.review` are tested through their parts (the copilot process with a stand-in, its command and environment, the copilot command of the run manager), not through the bridge with a project and a run.
- **Not done**: questions on runs without copilot (the Copilot view only shows for piloted runs); the preview of the data sent.
